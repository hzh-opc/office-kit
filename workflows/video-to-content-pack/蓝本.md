# 视频转内容包工作流（跨平台技能文档蓝本）

> **适用范围**：把一段/多段**视频内容**（含录屏、现场录制、屏幕+摄像头合成、工具生成视频、**电商直播回放**、**自媒体视频**、**采集设备录制**等）结构化为「修正版逐字稿 + 交付文档（形态可指定：讲义/文档/参考文档/教程/知识点汇总/文案，嵌步骤截图）+ 去边截图 + 按小节/产品细分视频 + 检索清单 + 文案」的内容包。
> **来源**：沉淀自 12 节课程交付实践（12 份逐字稿 + 12 份讲义 + 277 张去边截图 + 按逐字稿 217 段 / 按目录 32 段两种粒度小节视频），并扩展电商/企业内容交付场景（按产品切片 + 文案产出）。
> **核心原则**：本地优先、不上云；环境统一（复用套件 venv）、职责边界清晰；机械环节（建目录 / 归一化 / 记录链索引 / OCR 调度 / 去边 / 切片 / 导出 / 渲染 / 外发扫描 / 校验）走本工作流自带脚本 `tools/vcp.py`（runner 直跑、跨平台、可续跑），识别与生成类走 office-kit 组件（info-extract 转录·OCR·画面解读·摄取、summarize 摘要、doc-layout-aesthetics 精排 PDF / 腾讯文档）。
> **适用范围扩展**：与「录屏课程」相比，本工作流不假设输入一定是录屏——只要是可解析时间轴或可追溯来源的「视频内容」即适用；来源端（文件/直播/设备/自媒体）由 §0.6 与 §1.1 统一编排，下游（转录/抽帧/裁分/文案）对内容本身操作，与来源无关。
> **电商/企业场景说明**：电商直播回放、产品演示、种草短视频等，除「逐字稿+文档」外，通常需要**按产品切片**（一段视频含多个商品，按商品切出独立片段）并配套**文案**（卖点/口播/商品描述/短视频标题正文）。本工作流在 §3.5、§4.3、§5 专项支持，详见 §0.7 合规提示。
> **工作记录链原则（贯穿全文）**：每一阶段**只算一次、落盘为机器可读记录**，下游阶段只读上游记录、不再重算；重跑某阶段时复用上游记录，从而把"重复劳动"降到最低、并让每个产物可独立复核。详见 §0.4。

## 0. 跨平台路径与运行环境约定

### 0.1 路径占位符（按实际平台替换）

| `<DOC_LAYOUT>` | doc-layout-aesthetics 组件（精排 PDF / 腾讯文档） | `<OFFICE_KIT>/components/doc-layout-aesthetics` | `<OFFICE_KIT>\components\doc-layout-aesthetics` |

- **默认调用规则**：机械环节 → `vcp.py`（纯 Python、跨平台、不用 POSIX shell 方言）；摄取/转录/OCR/画面解读/摘要/排版 → office-kit 组件，且**统一经 `kit.py` 分发**，从而继承「外发必扫 DESEN」闸门；media **不再被默认路径引用**。
- **为什么去掉 media**（2026-09-22 重构）：① 抽帧本就由 info-extract 在转录时免费产出（D13 讲解段帧），无须另装抽帧栈；② 去边只需 PIL，套件 venv 已装；③ ffmpeg 用套件 venv 的 `imageio_ffmpeg` 内置静态二进制（本机实测 `ffmpeg-macos-aarch64-v7.1`）；④ 少一个环境 = 少一处版本漂移与装包成本。
- **直播链接/采集设备/自媒体**的摄取由 info-extract 承担（见 §0.6 来源状态表）：自媒体已支持；直播链接与采集设备的原生摄取（录制环节+边录边转+浏览器鉴权+增强 A–E）已在 info-extract 独立开发仓实现（`router.py --live` / `--device`），并于 2026-09-03 **同步进 office-kit `components/info-extract`（manifest 已登记 `live`/`capture`，部署副本 `<OFFICE_KIT>` 同步）**。工作流契约 `source=live`/`device` 直连原生路径；`source=live_fallback`/`device_fallback`（由 `vcp.py` 用套件 venv 的 ffmpeg 先录制为本地文件再转写）保留为录制完整性兜底（录制-转写策略与浏览器鉴权见 §10 与反馈文档）。

### 0.3 环境准备（跨平台）

**环境复用原则（套件级，唯一必需环境）**：`video-to-content-pack` 默认与 office-kit 所用的虚拟环境保持一致——统一复用 `~/office-kit/.venv`（套件唯一虚拟环境真相源，解析顺序见 `kit.py::_venv_dir`），工作流**不自建独立 venv**。机械步脚本、组件调用（info-extract / summarize / doc-layout）与 `kit` 自身均在该 venv 内解析。

**`precheck` 步自检三个前提**（失败即停，不浪费后续算力）：

1. **解释器依赖**：当前解释器能 `import PIL`、`import imageio_ffmpeg`；否则给出「改用 `~/office-kit/.venv/bin/python` 重跑」的明确指引（不静默降级）。
2. **ffmpeg 可用**：按四级探测链解析——`--param ffmpeg_bin` > 套件 venv 的 `imageio_ffmpeg`（**推荐，本机实测可用**）> media 环境 > 系统 `PATH`；全部落空时报错并给三选一指引，不静默失败。
3. **参数与来源**：`source` / `granularity` / `copywriting` / `digest` / `deliverable_render` / `cloud_upload` / `desen_gate` 取值合法；`source_uri` 必填，且文件来源时路径真实存在。

自检结论落 `<WORK_REC>/<节名>/run_context.json`（含解释器、ffmpeg 路径与来源、参数快照），供下游与复核引用。

**media 环境（可选，非必需）**：仅当历史脚本仍需 opencv / pydub 时使用；本工作流的默认路径**不引用**它（抽帧由 info-extract 完成、去边由 PIL 完成、ffmpeg 由套件 venv 提供）。缺失不影响主流程。

**组件前提**：确保 `<OFFICE_KIT_PY>` 可用，且含 info-extract（`components/info-extract/scripts/router.py`）、summarize、doc-layout-aesthetics 三个组件入口。info-extract 的在线/自媒体下载依赖 `yt-dlp`（按需 `pip install yt-dlp`）；直播/设备录制依赖 ffmpeg 设备采集能力（套件 venv 的 imageio-ffmpeg 已含，无需额外装）。

### 0.4 工作记录链原则（减少重复、支持复核）

每条内容/每节的处理都是一条**单向流水线**：上游产物落盘到 `<WORK_REC>/<节名>/`（或 `<WORK_REC>/<产品名>/`），下游只读不重算。

**阶段 → 机器可读工作记录 → 人类可读视图 → 被谁消费**（记录名已与 info-extract v0.6.4 的真实产物对齐）：

| 阶段 | 机器可读工作记录（落 `<WORK_REC>/<节名>/`） | 人类可读视图 | 被谁消费 |
|---|---|---|---|
| 0 摄取前置 | `run_context.json`（解释器 / ffmpeg 来源 / 参数快照） | — | index_records |
| 0/1 摄取+转录 | `ingestion_manifest.json`（来源/方法/合规声明）、`transcript_meta.json`（时长/语言/段落/产物路径） | `交付/<节>.{txt,md}`、`存档/<节>.{srt,json,correction.md}` | digest、authoring、cut_plan |
| 1b 摘要素览 | `digest.json`（tldr / 摘要 / 关键词 / 权重） | — | authoring（「本节速览」「关键词自测」） |
| 2 帧清单/OCR/去边 | `frame_index.json`（帧清单 + 指纹 + 去重标记）、`ocr_review.json`、`crop_manifest.json` | 抽帧预览图、`讲义截图_原始备份/` | frame_pick、illustrate、verify |
| 2b 帧智能判读（v0.5.0） | `slide_class.json`（知识承载 / 纯文字分类）、`anchor_check.json`（锚点漂移 + 最佳帧建议）、`naming_report.json`（命名规范 + 名实一致） | — | frame_pick、illustrate、verify |
| 3 逐字稿/交付文档/配图/文案 | `transcript_headers.json`、`delivery_spec.json`、`illustration_index.json`、`copywriting.json` | 交付文档 MD / 文案 MD / `视频时间轴与来源说明.md` | illustrate、cut_plan、export、verify |
| 4 目录/产品切片 | `catalog.json` / `catalog_diff.json`、`product_catalog.json` / `product_catalog_diff.json`、`cut_plan.json`、`blank_intervals.json`、`cut_manifest.json` | `视频裁切计划_待确认.md` | export、verify |
| 5 导出/渲染/上云 | `export_manifest.json`、`render_manifest.json`、`cloud_manifest.json` | `课程交付/README.md`、清单 CSV、`课程交付/PDF/*.pdf` | 用户 / 总目录 |
| 6 外发闸门/校验 | `desen_report.json`、`verify_report.json` | — | verify、用户 |
| 7 跨节汇总（v0.5.0） | `_work/aggregated_sections.json`（各节记录链 + 校验结论 + 配图实际计数） | `课程交付/00_课程总览_索引.md` 的自动索引区块 | 用户 |

**规则**：
1. **一次计算、落盘复用**：时长提取、帧清单与去重、OCR 复核、切片边界等易重算项，只在首次生成并记录；重跑后续阶段直接读记录。
2. **单一真源**：裁切以 `cut_plan.json` 为准；清单/索引由 `cut_manifest.json` 派生，不各自硬编码边界。
3. **指纹追踪**：`<WORK_REC>/pipeline_state.json` 由 runner 维护，记录每步状态 + `uses` + 产物路径 + **sha256 指纹**（对该步 `writes` glob 命中的文件逐个登记），便于判断是否需要重算、复核产物是否被改。
4. **可独立复核**：每个记录附"来源/命令/参数"（如 `run_context.json` 记解释器与 ffmpeg 来源），任意环节出问题可只重跑该环节（`kit workflow run … --step N`），不影响其他。
5. **跨平台**：记录统一 UTF-8 JSON/CSV，路径用 `pathlib` 相对 `<WORK_REC>` 解析。
6. **历史名已废**：`course_raw/<节>_raw.states.tsv`、`unique_states.json`、`frames_manifest.json` 均为 v0.3.0 的推演产物，**实际不存在**（info-extract 不产 `states.tsv`）；已由 `frame_index.json` 取代。全仓搜索 `tsv` 不再命中本工作流。

### 0.5 交付物形态（deliverable type）参数

**交付文档不是只有「讲义」一种形态**。除学员讲义外，同一节视频/逐字稿可定向产出为以下形态（用户按交付目标指定，可多形态并存）；电商/产品场景另增「文案」形态（可位于节级或产品级）：

| 形态 | 适用场景 | 推荐结构（§3.4 模板） | 产物文件命名 |
|---|---|---|---|
| 讲义 | 课堂随学、步骤跟练 | 本节速览 + 学习目标 + 按步骤嵌截图 + 关键词自测 + 易错点速查 + 一页带走 | `第NN节_讲义.md` |
| 文档 | 通用说明、制度/流程说明 | 概述 + 适用范围 + 主体条款/流程 + 相关口径/依据 + 参见 | `第NN节_文档.md` |
| 参考文档 | 备查手册、口径速查 | 条目化 + 关键定义 + 适用条件 + 例外/边界 + 出处索引 | `第NN节_参考文档.md` |
| 教程 | 操作指引、手把手 | 目标 + 前置条件 + 分步操作（嵌截图）+ 验证 + 常见问题 | `第NN节_教程.md` |
| 知识点汇总 | 复习/考点、提纲挈领 | 提纲 + 要点 + 关键定义/公式 + 易混淆点 + 索引 | `第NN节_知识点汇总.md` |
| 文案 | 电商/带货/种草、商品描述 | 卖点提炼 + 口播文案 + 适用场景 + 合规提示（见 §3.5） | `第NN节_文案.md` 或 `产品_XX_文案.md` |
| —（非形态，独立交付物） | 视频时间轴与来源溯源 | 来源与合规 + 章节时间轴 + 切片对照（由 `vcp.py export` 派生，见 §5.1） | `视频时间轴与来源说明.md` |

**规则**：
- **命名统一零填充（W2，硬约定）**：章号与图号一律**两位零填充**——交付文档 `第NN节_<形态>.md`、修正版 `第NN节_<标题>_修正版.md`、截图 `第NN节_图MM_<描述>.{png|jpg}`。`第7章` / `第7节` / `第07章` 三种历史写法并存曾导致 2 次踩坑；`vcp.py name-check` 与 `verify` 门禁 2 会校验零填充一致性，不再靠人工记忆。章节号比较一律按**数值**（`chapter_digits`），兼容历史产物。
- **形态是用户指定参数**（落在 §3 工作记录 `delivery_spec.json`，含 `type[]` / 可选 `extra_modules` / `generated_at`），驱动 §3.4 用哪套结构模板写稿；转录/抽帧/裁分等阶段与形态无关，照常执行。
- **可多形态并存**：同一节可同时产出 讲义 + 参考文档，分别成文件、互不覆盖（文件名带形态后缀）。
- **默认形态**：未指定时默认「讲义」，保持与历史交付一致。
- **截图引用**：所有形态均复用同一套去边截图（`讲义截图/`），按需要嵌入；引用校验（§6）对全部形态统一执行。
- **文案可产品级**：按产品切片（§4.3）时，文案以「产品」为粒度产出（`产品_XX_文案.md` + `copywriting.json`），与节级文档互补。

### 0.6 输入端来源（input sources）与摄取编排

视频内容的来源不止本地文件。下表统一编排各来源的摄取方式与责任环境；原生摄取与降级路径的双路状态见 §10 实现状态与 §11.4 降级矩阵。

| 来源类型 | 示例 | 摄取方式 | 责任环境 | 状态 |
|---|---|---|---|---|
| 视频文件 | 录屏 mp4、产品演示 mp4、本地回放 | 直送 `video_transcript`（抽音轨→Whisper） | office-kit(info-extract) | ✅ 已支持 |
| 自媒体(点播) | 抖音/小红书/B站/视频号/YouTube 视频 | `video_online`：yt-dlp 下载→转录；账号枚举+cookie+防风控 | office-kit(info-extract) | ✅ 已支持 |
| 直播链接 | 抖音/视频号/B站/YouTube **直播** | 原生：`router.py --live`（边播放边录制边转写，近实时出稿；健康探针/自动分段/断流重连/浏览器鉴权，增强 A–E）；兜底：`live_fallback`（先录制为本地文件再转写）。需登录态者 `--cookies-from-browser` 直连，失败回退**浏览器技能（browser-skill/agent-browser）持登录态**后再录制/捕获 | office-kit(info-extract) | ✅ **已实现并同步组件（P0，2026-09-03）** |
| 视频采集设备 | 摄像头/HDMI 采集卡/OBS 虚拟相机/DeckLink | 原生：`router.py --device`（边采集边录制边转写）；兜底：`device_fallback`（先采集录制为文件再转写，边转失败不影响录制完整性） | office-kit(info-extract) / `vcp.py` | ✅ **已实现并同步组件（P1，2026-09-03）** |
| 在线·加密视频 | DRM/需登录的视频 | yt-dlp 失败→浏览器播放中捕获（`--capture-path`） | office-kit(info-extract) | ✅ 已支持（回退） |

**摄取原则**：
- 所有来源最终归一为「本地视频文件 + `ingestion_manifest.json`」再进入 §1.2 转录；下游阶段（抽帧/裁分/文案）与来源解耦。
- **合规与风控**：直播/自媒体/设备涉及他人内容或平台条款时，仅处理用户有权访问的内容；批量抓取须遵守平台 ToS、开启限速（info-extract 默认约 3s 间隔）；加密/DRM 属法律灰区，显式提示风险、不规避版权保护。

### 0.7 企业/电商场景合规提示

- **广告法/极限词**：电商文案避免「最/第一/国家级」等违禁极限词；价格、促销、功效表述须留依据。文案产出（§3.5）应附「合规提示」模块，标出需人工核对的敏感表述。
- **品牌/商品术语表**：企业可维护 `brand_glossary.json`（品牌名/商品别名/禁用词），供逐字稿修正（§3.1）与文案生成（§3.5）消歧与脱敏复用（落 `<WORK_REC>/`）。
- **多账号/多店铺**：同一工作区可建 `品牌A/`、`店铺B/` 子目录隔离；`<WORK_REC>` 按节名/产品名隔离，避免串档。

## 1. 阶段一：内容摄取与转录（office-kit / info-extract）

**目标**：把任意来源的视频内容，归一为「本地文件 + 转录文本 + 时间轴」。

### 1.1 来源摄取（ingestion，按 §0.6 编排）

- **视频文件 / 自媒体点播**：
  ```bash
  <OFFICE_KIT_PY> <INFO_EXTRACT>/scripts/router.py "<文件或URL>" \
    --out <WORKSPACE>/按章节/第N节_标题/第N节.mp4
  # 自媒体账号批量：router.py "<账号URL>" --cookies-from-browser chrome --enum-interval 5
  ```
- **直播链接（原生已同步组件，兜底双路并存）**：原生 = `router.py --live <URL> --out <目录>`（边录边转 + 健康探针/自动分段/断流重连/`--cookies-from-browser` 鉴权）；兜底（`source=live_fallback`）先用 ffmpeg/media 录制为回放文件，再转写：
  ```bash
  <FFMPEG_BIN> -i "<直播URL>" -c copy <WORKSPACE>/按章节/第N节_标题/第N节_直播回放.mp4
  # 录制至直播结束（Ctrl-C 或超时），随后 router.py 转写
  ```
  > 直播同样建议"边录边转"：录制同时持续送 `video_transcript`，不可行再先录后转（与 §0.6/§10 一致）。需登录态的直播先用浏览器技能持登录态再录制。
- **采集设备（原生已同步组件，兜底双路并存）**：原生 = `router.py --device <设备> --out <目录>`；兜底（`source=device_fallback`，由 Agent 按平台组装）：
  ```bash
  # macOS 采集 OBS 虚拟相机/桌面：
  <FFMPEG_BIN> -f avfoundation -i "1:0" <WORKSPACE>/.../第N节.mp4
  # Windows 采集 HDMI 采集卡(dshow)：
  <FFMPEG_BIN> -f dshow -i video="USB Video" <WORKSPACE>/.../第N节.mp4
  ```
  > 设备采集建议支持「边录边转」：后台持续录制，定期把已录制片段送 `video_transcript`，直播/长录制场景可近实时出稿。

- **工作记录**：`ingestion_manifest.json`（`{source_type, source_url/device, method, raw_file, duration_sec, fetched_at, provider_meta}`），供 §1.2 与总目录消费；自媒体/直播/设备来源须记录来源与合规声明。

### 1.2 转录（transcription）

- **输入**：归一后的章节视频（或任意来源单段视频）。
- **工具**：**经 `kit.py` 调 `extract`**（info-extract，底层 faster-whisper 本地推理 + VAD 分块；模型默认 small，术语密集/口音重时用 `--param whisper_model=medium` 提升）。**必须经 kit.py 分发**，方能继承「外发必扫 DESEN」闸门（交付文本可能含敏感信息，隐性外发）。
- **真实产物（info-extract v0.6.4 实测）**：
  - `交付/<节名>.txt` / `交付/<节名>.md` —— 成品逐字稿，**下游 authoring 的直接输入**；
  - `存档/<节名>.srt` / `存档/<节名>.json` / `存档/<节名>.correction.md` —— 分段与时间轴，**`index_records` 从 `.json` 抽时长/语言/段落**；
  - `<节名>_frames/` —— **D13 讲解段帧（转录时免费产出）**，即 §2 的抽帧主体，无须另跑抽帧器；
  - `<节名>_keyframes/` —— 仅在显式加 `--vision` 时产出整视频关键帧。
- **在线/自媒体/直播/设备原生路径已含转录**（边录边转），故契约 `transcribe` 步对它们跳过（`when: source in file,live_fallback,device_fallback`）。**只跑一次**，下游（2/3/4）均读此记录。

## 2. 阶段二：帧清单索引 + 选帧命名 + OCR 复核 + 截图去边

> **v0.4.0 关键变化**：抽帧不再单独执行——**info-extract 在转录时已免费产出 D13 讲解段帧**（`<节名>_frames/frame_<秒>_<百分秒>.png`，文件名自带时间戳）。本阶段因此退化为「**索引 → 选帧 → 复核 → 去边**」四件事，机械部分全部由 `vcp.py` 承担。
> **v0.5.0 增补（§2.5–§2.7）**：在「索引/OCR」与「选帧」之间，以及「写作」之后，补三道具机器判读能力的**机械门**——幻灯片价值分类（纯文字页不截图，W9）、锚点自检与最佳帧建议（W11/W13）、命名规范与名实一致核对（W2/W10）。三者都是**建议 + 门禁**双重角色：给 Agent 高质量输入，同时在 `verify` 阶段自动兜底。
> **工作帧留存策略（W4，统一约定）**：`_work/<节名>_frames/` 与 `_work/<节名>_keyframes/` 是 info-extract 的**原始产出，一律保留**（可追溯、可重截）；`_work/frames_ocr/<帧名>/` 与 `_work/naming_ocr/<图名>/` 是**可再生的 OCR 缓存**（断点续跑用），可按需清理、不计入记录链完整性；除上述三处外**不再另建 `_work` 工作帧目录**——历史上「某章中间帧留在 `_work`、其余章不留」的不一致到此为止。

### 2.1 帧清单索引（`vcp.py index-records` → `frame_index.json`）

- 扫描 `<节名>_frames/`（D13 讲解段帧）与 `<节名>_keyframes/`（若存在，`--vision` 产出），用文件名正则解析时间戳：
  - D13 帧 `frame_<sec>_<centi>.png` → `ts = int(sec) + int(centi)/100`（**注意不是小数秒**：`frame_0006_00.png` = 6.0s）；
  - 关键帧 `*_kf_*_<n>.png` → `ts = int(n)/100`（`600` → 6.00s）。
- **去重判据用 16×16 灰度 MAD，不是 aHash/dHash**：课程/直播画面多为「大面积纯底 + 少量元素」的幻灯片，aHash 会把纯底占绝对多数的不同帧哈希成同一个值（**实测两张内容不同的幻灯片 aHash 距离 = 0**）；改逐像素平均绝对差后区分度良好（**实测完全相同帧 MAD=0.0、内容不同帧 MAD≥3.8**），阈值默认 2.0（`--dup-mad` 可调）。
- 产出 `frame_index.json`：`[{idx, time, file, sha256?, ocr_head?, dup_of?}]`，重复帧保留首现、其余记 `dup_of`。**只算一次**，后续复用。

### 2.2 选帧与命名归位（**创作步** `frame_pick`，Agent 执行）

- 输入：`frame_index.json`（候选帧）+ `ocr_review.json`（画面文字）+ **`slide_class.json`（帧价值分类）** + 逐字稿正文。
- 判据：「相似度只是筛子不是裁判」——须**逐张核对「画面 = 文件名 = 图注 = 正文」四一致**；复制并命名为 `<WORKSPACE>/课程交付/讲义截图/第NN节_图MM_描述.{png|jpg}`（描述用中文短句）。
- **纯文字页不截图（W9）**：`slide_class.json` 判为 `text_only` 的帧（封面 / 目录 / 总结 / 过渡 / 条目页）**不生成截图**，改在交付文档中以 Markdown 列表 / 缩进 / 引用块呈现（§3.7）。
- **命名由画面内容驱动（W10）**：描述词应取自该帧**画面文字（`ocr_review.json` 的 `ocr_text`）**，**不得仅凭该段主题猜测**——历史上「文件名整体后移一位」「两张图名互换」均因按段落主题猜名所致。命名后由 §2.7 的 `name-check` 做一次「文件名关键词 vs 帧 OCR 文本」一致性核对。
- **命名格式（W2）**：章号/图号零填充（`第07节_图03_…`）、不含空格与 `< > : " / \ | ? *` 等特殊字符。
- **电商增强**：商品上架/演示画面、价格牌、SKU 条码等可加 `商品`/`价签` 锚点标签，便于 §4.3 按产品切片时定位。

### 2.3 OCR 复核（`vcp.py frames-ocr` → `ocr_review.json`）

- 对 `frame_index` 选中帧**逐帧独立子进程**调 `extract --type ocr`：单帧一进程，**防长视频批量 OCR 的内存累积 OOM**；已处理帧跳过，**支持断点续跑**。
- 产出 `ocr_review.json`：`[{filename, ocr_text, ocr_head, ...}]`，并回填 `frame_index.json` 的 `ocr_head`（供选帧时快速判读）。
- 单帧失败逐帧记录、不静默，不影响其余帧。

### 2.4 截图去边（`vcp.py crop` → `crop_manifest.json`）

- **保守算法（PIL，套件 venv 内，不再依赖 media）**：估计边缘背景灰度 → 前景掩码 → 内容边界 + pad → 强制护栏「保留 ≥55% 面积 + 单边裁掉 ≤200px + 边缘须近纯色暗底（std≤20）」。两种边缘：纯黑录制边框直接裁；深灰任务栏须加标准差护栏区分（实测多批课程不存在连续纯色可裁带，仅去黑边）。
- **流程**：先备份原图到 `课程交付/讲义截图_原始备份/`，再就地裁剪覆盖，**文件名不变**。
- **工作记录**：`crop_manifest.json`（`[{src, dst, cropped_box, keep_ratio}]`）。
- **顺序约束（v0.4.0 修正）**：去边**必须在配图（§3.7）之前**——配图引用的是去边后的成品图。v0.3.0 曾把去边排在配图之后（逻辑倒置），已在 §3.6 步序中改正。

### 2.5 幻灯片价值分类（`vcp.py classify-slides` → `slide_class.json`）

**要解决的问题（W9）**：默认「遇到幻灯片就截图」导致过度截图——实测某 11 章课程 169 张截图里 **64 张（38%）是纯文字页**（课程封面 / 目录 / 总结 / 条目 / 过渡页），没有知识性画面，本应文字化呈现。分类后截图量可降到约 105 张，讲义更聚焦、体积更小。

- **双信号判据**（任一单独都不可靠，故并用）：
  1. **文字页形态特征**：OCR 文本命中封面/目录/总结/过渡词表（→ `cover` / `toc` / `summary`），或结构特征命中（文字框 ≤3 且字数 ≤24 → `transition`；行数 ≥3 且短行占比 ≥80% → `item_list`）；
  2. **画面墨量 `ink_ratio`**：与主色差异显著的像素占比（96×96 采样）。幻灯片多为「大面积纯底 + 少量元素」，纯文字页墨量低、含照片/图解页墨量高。
- **判定**：`形态特征命中 && 字数 ≤ char_max && 文字框 ≤ box_max && ink ≤ slide_ink_max` → `text_only`；否则 `knowledge`。
- **墨量是否决项（安全阀）**：命中文字页特征但墨量高 → 仍判 `knowledge` 并注明理由——**宁可多留一张图，也不漏掉知识画面**。
- **产出**：`slide_class.json`（每帧 `kind` / `subtype` / `ink_ratio` / `num_boxes` / `char_count` / `ocr_head` / `reason` / `review_required`）+ 统计 + `text_only` 帧清单。
- **如何使用（重要）**：分类是**建议不是裁判**——`review_required`（`cover`/`transition`/`item_list`）的帧须人眼复核后再定；`text_only` 帧的处置见 §3.7。阈值可调：`--param slide_ink_max`（默认 0.12，越小越严）。
- **配套 OCR 字段**：`frames_ocr` 步已把 `fields.num_boxes` 落进 `ocr_review.json`，分类器直接消费，无需二次 OCR。

### 2.6 锚点自检与最佳帧建议（`vcp.py anchor-check` → `anchor_check.json`）

**要解决的问题（W13 + W11）**：逐字稿的 `▶` 锚点存在**段级漂移**（实测第 7 章「亮调/暗调」标在 96:05、实际课件页在 100:05+），盲信锚点截帧就会截错；另有 4 处「未截到最佳画面」（把保时捷页当麦当劳、截到总结页而非作品页、只截到「亮调」漏「暗调」）。

- **锚点来源（自动择一）**：显式 `--doc` > `课程交付/逐字稿_修正版/` > `_work/<节>/交付/`；两个来源分别对应 `▶ **MM:SS**` 与 `[MM:SS] 文本` 两种行格式（`mode` 字段区分）。
- **判据**：对每条锚点，在 `±anchor_window` 秒（默认 10s）内取帧，用**该锚点所属标题的关键词**（无标题时退化为正文关键词）与该帧 OCR 文本做命中打分，排序取最优。
- **产出与语义**：
  - `ok`：窗口内存在命中帧；
  - `drift`：窗口内有帧但关键词全不命中 → 锚点疑似漂移或截到了相邻页；
  - `no_frame`：窗口内根本无候选帧；
  - `indeterminate`：锚点无标题可依（成品逐字稿的 `[MM:SS]` 行，关键词来自口语正文，与画面文字本就不必重合）→ **不下漂移结论**，只给候选帧供人工判断。
  - `best`：建议采用的最佳帧（OCR 匹配度最高，含 `delta_sec` 相对锚点的偏移）。
- **如何使用**：`illustrate`（§3.7）以 `best` 为最佳截取依据；`drift` / `no_frame` 项须**抽帧目视确认**后重截（勿盲信锚点），并在 `illustration_index.json` 追加 `recaptured` 审计字段。`verify` 门禁 3 校验 `drift_count == 0`。

### 2.7 命名规范与名实一致核对（`vcp.py name-check` → `naming_report.json`）

**要解决的问题（W2 + W10）**：命名三套不一致（`第1章` / `第1章_静物摄影入门` / `第01章_图01`）已踩坑 2 次；另有 5 张截图**文件名与画面错位**（第 2 章图 06/07 命名整体后移一位、第 7 章图 20/23 名互换），且因错位挂错段落。

- **① 命名规范（纯字符串校验）**：文件名须匹配 `第NN节_图MM_中文短描述.{png|jpg}`；章号/图号零填充；无空格、无 `< > : " / \ | ? *`；缺中文描述告警。
- **② 名实一致（OCR 核对）**：对每张交付截图 OCR（**subprocess-per-image + 缓存续跑**，`_work/naming_ocr/`），把**文件名描述词 + `illustration_index.json` 的 `anchor_para`** 与该图 OCR 文本比对；关键词 **0 命中 → `mismatch` 告警**（画面里完全没有名字所声称的内容）；OCR 无文本 → `unverifiable`（不判不符，如纯实拍作品页）。
- **产出**：`naming_report.json`（逐图 `pattern_ok` / `issues` / `ocr_head` / `overlap` / `verdict` + 统计）。
- **如何使用**：`mismatch` 须抽帧目视确认后**重命名或重截**；`verify` 门禁 2 对「命名规范」硬校验、对「名实一致」软告警。可关：`--param naming_check=off`（跳过整步）或 `naming_ocr=off`（只做字符串校验）。

## 3. 阶段三：逐字稿修正与交付文档/文案编写（形态可指定）

- **修正版逐字稿（Markdown）**：
  - 修正语音识别错词，建术语替换表（行业/品牌术语，见 §0.7 `brand_glossary.json`）。
  - **术语替换表用结构化围栏块（W14，硬约定）**：以 `<!-- vcp:glossary begin -->` … `<!-- vcp:glossary end -->` 包裹，块内每行 `原词 → 修正词`。**为何**：表里的「识别原词」列（如「进屋摄影 → 静物摄影」）在全文字符串扫描时形似 ASR 残留误识，审计脚本曾据此误报 15 处；结构化围栏让下游**显式跳过**该块，根除误判。
  - 按 `▶ **MM:SS**` 标时间节点，按「讲 / ## / ###」分层。
- **交付文档（Markdown，形态可指定）**：
  - 默认形态「讲义」结构见 §3.4；其他形态按 `delivery_spec.json` 指定。
  - **时间锚点必须下传（W1，硬约定）**：修正版里的 `▶ mm:ss` 要**随知识点段一起带入交付文档**（高置信段落内联到对应段标题后）。**为何**：讲义是学习主件，锚点不下传则读者无法从讲义跳回视频，视频课讲义退化为纯文本（实测某课程 183 个锚点 → 讲义 0 个）。`verify` 门禁 5 校验「交付文档内联 ▶ 不得为 0」。
  - **降级 / 未校对声明置顶（W3，硬约定）**：交付文档与修正版**文首**须有一行状态声明；逐字稿未经纠正模型校对时须显式写出（如「原始逐字稿未经 AI 纠正模型校对，术语订正见『术语替换表』」），不得只留在 manifest 的 audit 字段里。
  - 引用：`![图NN](<../讲义截图/第NN节_图NN_描述.jpg>)`，各形态统一复用同一套去边截图。
  - 引用校验正则：`!\[[^\]]*\]\(<?([^)>]+)>?\)`，按 `os.path.dirname(md)` 解析相对路径。
- **工作记录（关键，供阶段四消费）**：`transcript_headers.json` —— **一次性提取**全部带时间戳标题及 `start/end` 秒数，落 `<WORK_REC>/<节名>/`。阶段四裁分/合并/按产品直接读此文件，**不再重复解析逐字稿**。

### 3.4 交付文档形态结构模板

按 `delivery_spec.json` 的 `type` 选用对应结构；同一节可多形态并存（文件名带形态后缀，见 §0.5），互不覆盖。

| 形态 `type` | 推荐结构（自上而下） | 截图嵌入 | 典型用途 |
|---|---|---|---|
| `讲义` | 文首状态声明 → 本节速览表 → 学习目标 → 时间轴指针行 → 按步骤嵌截图（含内联 `▶ mm:ss`）→ 关键词自测［记忆/理解/应用］ → 易错点速查［高频/低频］ → 一页带走 | 全程嵌入步骤截图 | 课堂随学、步骤跟练 |
| `文档` | 概述 → 适用范围 → 主体条款/流程（可嵌关键截图）→ 相关口径/依据 → 参见 | 关键处嵌入 | 制度/流程说明、通用文档 |
| `参考文档` | 条目化目录 → 关键定义 → 适用条件 → 例外/边界 → 出处索引 | 少嵌，必要处嵌 | 备查手册、口径速查 |
| `教程` | 目标 → 前置条件 → 分步操作（逐环节嵌截图）→ 验证 → 常见问题 | 分步嵌入 | 操作指引、手把手教程 |
| `知识点汇总` | 提纲 → 要点 → 关键定义/公式 → 易混淆点 → 索引 | 按需嵌入 | 复习/考点、提纲挈领 |
| `文案` | 卖点提炼 → 口播文案(可直接念) → 适用场景/人群 → 合规提示 → 可选标题正文 | 关键商品图嵌入 | 电商/带货/种草、商品描述 |

- 各形态共用同一套去边截图，不重复抽帧；引用校验（§6）对全部形态统一执行。
- 结构为「推荐」而非强制：用户可追加「案例」「FAQ」「变更记录」等模块。
- **复习分层（W8，讲义增强项）**：「易错点速查」每条标 `[高频]` / `[低频]`；「关键词自测」每题标 `[记忆]` / `[理解]` / `[应用]`（布鲁姆式分层）。目的是让复习有取舍依据，而非平铺通用模板。
- **时间轴指针行（W12，讲义硬约定）**：讲义**不内嵌完整时间轴大表**（实测塞进每章会干扰学习）；正文只保留内联 `▶ mm:ss` 轻锚点，并在文首留一行指针——「视频时间轴与转写来源说明（含降级声明）见《视频时间轴与来源说明.md》」。完整表由 `vcp.py export` 派生为独立交付物（§5.1）。
- **纯文字页文字化（W9）**：`slide_class.json` 判为 `text_only` 的页面（封面 / 目录 / 总结 / 过渡 / 条目页）在正文中以 Markdown 列表 / 缩进 / 引用块呈现，并注明取自视频的哪个时间点，不插截图。

### 3.5 文案生成（电商/产品场景，形态=`文案`）

文案可从「节级」或「产品级」产出；产品级文案与 §4.3 按产品切片联动。

- **输入**：成品逐字稿（`交付/<节>.txt`）+ `ocr_review.json`（画面文字）+ 可选 VLM `vision_caption`（商品画面）+ `brand_glossary.json`（品牌/禁用词）。
- **生成逻辑**：
  1. **卖点提炼**：从转录+OCR 抽取商品名、核心卖点、价格/规格、适用人群；去重合并。
  2. **口播文案**：按时间顺序组织为可直接念的口播稿（保留 `▶ MM:SS` 锚点对应视频片段）。
  3. **标题/正文**：电商短标题 + 种草正文（小红书/抖音风格可切换）。
  4. **合规提示**：标注极限词/价格/功效等需人工核对的敏感表述（§0.7）。
- **产品级文案**（§4.3 联动）：每个产品一段，含「产品名/卖点/口播/标题正文/合规提示/对应视频片段路径」。
- **工作记录**：`copywriting.json`（`[{scope:"section|product", ref, selling_points[], script, title, body, compliance_notes[]}]`），供 §5 导出 `文案汇总.md` 与产品清单复用。

### 3.7 交付文档配图（illustration-spec）

把 §2.4 已去边截图，按「三条标准 + 图文位置判据」插入 `delivery_spec.json` 指定的交付文档对应位置；不改写正文、不重抽帧，登记 `illustration_index.json` 供 §6 verify 跨检。

- **三条标准**（与 workflow.json `illustrate` 步一致）：
  1. **内容匹配**：每段正文配与其语义最贴合的截图，而非装饰性/随意配图。
  2. **数量按需**：配图数量由内容密度与展示需求决定——信息点多则多配，单点说明则少配，不强行凑数也不漏关键步骤图。
  3. **密集合成**：同一段文字配图较多时，按合适形式裁切/拼接为一张合成图（montage），避免连续堆砌多张原图冲散阅读节奏。
- **图文位置判据**（硬违例必须为 0）：
  - **A 真错位**：图与所说明的正文不在同一小节/邻近段落，读图时找不到对应讲解 → 违例。
  - **B 多图堆叠**：同一段落连续 3 张及以上原图无正文间隔 → 违例（应合成或分散）。
  - **C 图先于文**：图出现在讲解它的正文之前（读者先见图后见说明）→ 违例。
  - **D 裸图堆叠**：纯图片段（无任何承上启下文字）连续出现 → 违例。
  - **E 类合法例外**：成组前后对比图（如「调色前/后」）、操作步骤序列图等经确认属合理展示的，放行不计入 D 违例。
- **登记**：`illustration_index.json` —— 逐图记录 `{chapter, img, anchor_para, standard_matched, position_class}`；纯文字页移出时在该条目加 `text_replaced: {date, moved_to, note}`（其 `img` 不计入交付截图数）。供 §6 verify 跨检 A/B/C/D/E 与「索引 ↔ 磁盘」一致性。重截须追加 `recaptured: {timecode, reason, source}` 审计字段（W11）。
- **纯文字页不配图（W9）**：`slide_class.json` 判为 `text_only` 的页面**不插图**——正文转 Markdown 列表 / 缩进 / 引用块，原图移入 `课程交付/讲义截图_文字页替代/`（保留可回溯，但**不得**被交付文档引用；verify 门禁 1 会校验）。
- **最佳截取以 OCR 为准（W11）**：插图前用 `anchor_check.json` 的 `best` 候选核对——目标帧 OCR 不含该锚点核心关键词时，在锚点 ±`anchor_window` 秒内改用匹配度最高的帧重截；**重截一律先抽帧目视确认**，不盲信时间锚点。
- **命名由画面内容驱动（W10）**：`alt` / 文件名描述取自该帧 OCR 文本；命名后由 §2.7 `name-check` 做「文件名关键词 vs 画面 OCR」一致性核对。
- **覆盖率告警（W7）**：`verify` 门禁 4 对「字数 ≥ `coverage_min_chars`（默认 200）且无图的 H3 知识点段」列告警，提示补图（纯文字段除外）。
- **通用方法**（零项目硬编码，可跨项目复用）：详见 `office-kit/workflows/video-to-content-pack/illustration-spec.md`（七步闭环 + 三条标准 + A–E 判据 + 「幻灯片价值分类器 / 帧内容核对 / 命名一致性」三节）。

## 4. 阶段四：切片 / 合并（三种粒度：时间线 / 目录 / 产品）

**目标**：把「按章节」整段视频，按**逐字稿时间线 / 课程目录 / 产品(可指定)** 切成知识点或商品小节；支持合并/拆分/增量重切。

裁分粒度有三个来源，按 §4.2.1（目录）/§4.3.1（产品）优先级择一：
- **A. 按课程目录**（§4.2→§4.4→§4.5）——以用户/运营提供的目录为准。
- **B. 按逐字稿时间线**（§4.1）——无目录时由标题时间戳自动切。
- **C. 按产品切片**（§4.3）——电商/带货场景，按商品(用户指定或检测)切独立片段并配套文案。

### 4.1 按逐字稿时间线裁分（无目录时的兜底）
- 直接读 `transcript_headers.json`（**不重解析逐字稿**）；过滤 <15s 过密边界。
- 边界：上一段 end = 下一段 start；末段 end = 视频真实时长（PyAV 读 `duration`，来自 `transcript_meta.json`）。
- 切割：`ffmpeg stream-copy`；输出 `<WORKSPACE>/按章节/第N节_标题/小节_按转录/第NN节_II_标题.mp4`。
- **合并（反向上粗化）**：按「讲/课」或用户指定层级合并为粗粒度；更细则按 `###` 拆分。

### 4.2 目录获取机制（catalog acquisition）
#### 4.2.1 来源优先级（用户显式 > 自动生成）
| 优先级 | 来源 | 形式 | 处理 | 环境 |
|---|---|---|---|---|
| ① 用户显式 | 目录文件 / 口述 | 图片/文本/Markdown/CSV/DOCX/PDF/结构化模板 | 解析 → `catalog.json` | 图片 OCR 走 office-kit |
| ② 自动生成候选 | 逐字稿 | 带时间戳标题 | 抽 `transcript_headers.json` 生成候选，交用户确认 | Agent+人工 |
> 自动生成仅作兜底；任何自动目录须梳理后由用户确认再切。

#### 4.2.2 图片目录识别（office-kit RapidOCR，自适应切块）
- 按图高估算 band 数（每块≈1200px，重叠 3%），逐块 RapidOCR，按坐标排序还原顺序；落 `catalog.json`（`source:"image_ocr"`/`raw_lines`/`parsed`）。

#### 4.2.3 结构化目录模板（免 OCR、零边界歧义）
- CSV/JSON 模板（`节次,小节标题,起始时间,结束时间` / 等价 JSON），解析后落 `catalog.json`（`source:"user_template"`）；亦作 OCR 结果回填格式。

#### 4.2.4 文本/文档目录解析
- 文本/Markdown 按行解析层级+时间戳；DOCX/PDF 先提取文本再解析；一律落 `catalog.json`。

### 4.3 按产品切片（product slicing，电商/带货场景）
#### 4.3.1 产品来源优先级
| 优先级 | 来源 | 形式 | 处理 | 环境 |
|---|---|---|---|---|
| ① 用户指定产品清单 | 产品文件/口述 | CSV/JSON（`产品名,起始,结束,[卖点关键词]`）/ 模板 | 直落 `product_catalog.json` | Agent+人工 |
| ② 转录关键词提取 | 逐字稿+OCR | 商品名/品牌词命中 | 关键词检索逐字稿+OCR 定位时间区间 → 候选 `product_catalog` | Agent+office-kit |
| ③ VLM 画面检测 | 关键帧 | 商品上架/演示画面 | 本地 VLM 检测商品出现区间 → 候选 `product_catalog` | office-kit(VLM) |
> 优先级同目录：用户显式指定优先；②/③ 为辅助，产出候选后**交用户确认再切**。

#### 4.3.2 产品目录结构
- `product_catalog.json`：`{source, products:[{name, start, end, keywords[], selling_points[]}]}`。
- 同名产品多段 → 合并或保留多段（用户定）；时间区间冲突/重叠 → 标 `time_mismatch` 交确认。

#### 4.3.3 产品差异/确认（类比目录差异）
- 生成 `product_catalog_diff.json`：转录有商品未列 / 清单有稿无 / 标题/时间冲突；OCR 模糊匹配标红（ratio<0.6）。人类可读 `产品切片差异报告.md` 交确认。

#### 4.3.4 执行切片 + 关联文案
- 单一真源 `cut_plan.json` 增 `granularity:"按产品"`、`product_ref`；执行 `ffmpeg stream-copy` 到 `小节_按产品/产品_XX_标题.mp4`。
- 联动 §3.5 文案：每段从 `copywriting.json` 取该产品文案，产出 `产品_XX_文案.md`；文件名用产品名（交付友好），`cut_manifest.json` 记录 `transcript_title`/商品别名溯源。

### 4.4 解析与边界映射（时间戳优先级 + 空白检测）
#### 4.4.1 时间戳来源优先级
1. **目录/产品清单自带时间戳** > 2. **逐字稿讲/课时间戳** > 3. **等分到段**。
2. **目录/产品时长与源不一致一律以源为准**（平台剪辑版偏短）；边界以 `transcript_meta.json` 的 `duration_sec` 为准。
#### 4.4.2 粒度映射
- 目录比讲次粗→合并；细→拆分；标题不一致以目录/清单为准，保留逐字稿别名（§4.5/H）。
- 产品切片：用户指定时间区间直接采用；仅给产品名 → 由 ②/③ 候选区间，确认后采用。
#### 4.4.3 空白间隔/末段边界自动检测
- `blank_intervals.json`：静音段（silencedetect）+ 画面冻结 + OCR 无变化连续 >N 秒 → 判空白；末段取最后有效内容终点。裁切跳过空白区间。

### 4.5 裁分 / 合并执行（多粒度共存 + 增量重切 + 保留别名）
1. **生成裁切计划**（单一真源 `cut_plan.json`）：含 `granularity`、`source`、各段 `sec/idx/title/transcript_title/start/end`、合并/拆分/产品依据、空白跳过。
2. **人类可读视图**：`视频裁切计划_待确认.md`（派生），回显；用户可调整某段起止/标题，修订后再确认。
3. **执行裁切**（ffmpeg stream-copy，源视频不动；ffmpeg 取套件 venv 的 imageio-ffmpeg）：
   - **输出目录参数化**：`小节_按目录/`、`小节_按转录/`、`小节_按产品/` 天然共存，互不覆盖；**无需 rename 备份旧片段**。
   - **增量重切**：比对 `cut_plan.json` vs `cut_manifest.json`；未变段复制/硬链接，仅变化段执行 ffmpeg。
   - **保留别名**：文件名用目录/产品标题；`cut_manifest.json` 与清单记录 `transcript_title`/商品别名 + 溯源。
4. **工作记录**：`cut_manifest.json`（`[{filename, start, end, duration, transcript_title/product_name, src_video_sha}]`）。

### 4.6 踩坑记录（跨平台通用）

| 坑 | 现象 | 修复 |
|---|---|---|
| 时间戳含「前后」后缀 | 正则丢整条边界 | 正则只捕首个 `MM:SS–MM:SS` |
| 只取 `##` 漏 `###` | 子标题被合并成长片 | 连同 `###`；或直接读 `transcript_headers.json` |
| 视频目录 glob 用错前缀 | 文件夹以「第」开头匹配空 | 用 `第{cn}节*` |
| stream-copy 段首偏移 | 关键帧对齐 ≤1 帧微偏 | 接受（时长精确即可） |
| 路径分隔符 | Win `\` / mac `/` | 脚本内 `pathlib`，禁硬编码 |
| **目录图片被会话过滤** | 多模态读取失败 | 走 office-kit RapidOCR 自适应切块 |
| **目录粒度 ≠ 讲次** | 段数与用户目录不符 | 以目录为准合并/拆分，先确认再切 |
| **批量删除旧派生片段触发护栏** | 旧 `小节/` 超阈值删需确认 | 参数化输出目录，多粒度共存，不删旧 |
| **目录/产品时长与源不一致** | 平台剪辑版偏短 | 时间边界以源为准，清单只定段数/标题 |
| **OCR 误差漏检** | 命名偏离 | OCR 模糊匹配标红进差异报告 |
| **增量重切全量重跑** | 只调一段也全量切 | 比对 plan vs manifest，仅重切变化段 |
| **模板缺字段** | CSV 缺起/止 | 回退逐字稿时间戳/等分，不中断 |
| **直播/设备来源缺录制环节** | （历史坑，已解决）原生摄取已同步组件 | 首选 `source=live/device` 原生路径；`live_fallback/device_fallback` 保留兜底（先录制为本地文件，§1.1） |
| **电商文案极限词合规** | 产出违禁词 | §3.5 文案附合规提示模块，标敏感表述 |

- 段数示例（同课程多粒度）：按逐字稿 `###` 共 217 段；纯 `##` 119 段；按目录严格 32 段；按产品切片段数=产品数（如一场直播含 8 商品→8 段 + 8 份文案）。多种粒度可并存不同输出目录。

## 5. 阶段五：导出检索清单 + 渲染 + 云端交付（`vcp.py`）

### 5.1 清单 / 索引 / 汇总导出（`vcp.py export`，**无论粒度均执行**）

- 全部由 `cut_manifest.json` + `catalog.json`/`product_catalog.json` + `copywriting.json` + 交付目录 **派生**（单一真源，不各自硬编码），并写 `export_manifest.json` 留痕：
- **小节视频清单** `<WORKSPACE>/课程交付/小节视频清单.csv`（utf-8-sig）：列 `节次/节标题/段号/段标题/逐字稿对应标题(别名)/文件名/相对路径/起始/结束/时长_秒/粒度来源`。
- **产品切片清单** `<WORKSPACE>/课程交付/产品切片清单.csv`：列 `产品名/对应节次/段号/视频文件/起始/结束/时长_秒/文案文件`。
- **分节清单** `课程交付/<节文件夹>/小节清单.md`；**全量索引** `小节视频索引.md`。
- **文案汇总** `<WORKSPACE>/课程交付/文案汇总.md`（或各 `产品_XX_文案.md`）：由 `copywriting.json` 派生，含卖点/口播/标题正文/合规提示。
- **交付总索引** `课程交付/README.md`。
- **裁切计划留痕** `视频裁切计划_待确认.md`。
- **修正历史缺陷**：v0.3.0 把导出挂在 `granularity!=none` 下，导致「仅单节交付」时**文案汇总与交付索引永不导出**；v0.4.0 改为**无条件执行**（无切片时清单为空，但索引照出）。
- **视频时间轴与来源说明（W12，v0.5.0 新增）**：<WORKSPACE>/课程交付/`视频时间轴与来源说明.md` —— **独立交付物**，由 `ingestion_manifest.json`（来源与合规）+ 逐字稿锚点（→ 章节时间轴表）+ `cut_manifest.json`（切片对照）**纯派生**，不含人工填写项。讲义只留一行指针（§3.4），解决「完整时间轴大表塞进每章干扰学习」的问题。
- **交付总索引的配图数自动核对（W5，v0.5.0 新增）**：`课程交付/README.md` 增「配图核对」表——`磁盘截图（讲义截图/）` / `交付文档引用（去重）` / `文字页替代（讲义截图_文字页替代/）` / `配图索引有效条目（illustration_index.json）` **全部由脚本实际计数**。历史教训：该数曾手工填错 2 次（全章填 19）；此后一律不手工填，`verify` 门禁 6 亦做「索引 ↔ 磁盘」交叉校验。

### 5.2 交付物渲染（`vcp.py render`，`deliverable_render!=off`，doc-layout 组件对接）

- 逐份 Markdown 交付物 → doc-layout-aesthetics 的 `md-pdf` → 中文精排 PDF（含封面、CJK 避头尾、**图片按相对路径内联**——本机实测可用）→ `课程交付/PDF/`。
- 写 `render_manifest.json`（`[{src_md, pdf, ok, rc, stderr_tail?}]`）；**失败逐份报错、不静默**。

### 5.3 云端交付（`vcp.py cloud-upload`，`cloud_upload==tencent`，**显式外发**）

- doc-layout-aesthetics 的 `tencent-doc` 把交付文档上传腾讯文档并套用版面美学。
- **经 `kit.py` 分发**，命中敏感信息由外发闸门**先阻断**，须用户 `--confirm-raw` 确认（`external_kind=explicit`）。写 `cloud_manifest.json`。

### 5.4 跨节状态自动汇总（`vcp.py consolidate`，v0.5.0 新增，W6/W5）

多节课程（如 11 章）跑完后，需要一份「全课状态总览」——历史上靠**事后手工补** `pipeline_state.json` 的 `aggregated_sections` 字段，既易漏又无校验。

- **产出 1**：`<WORK_REC>/aggregated_sections.json`（**落 `_work/` 根**）—— 逐节记录「章节号 / 交付文档数 / 修正版数 / 截图数 / 文字页替代数 / 配图索引有效条目数 / verify 硬失败数与告警数 / 记录链齐全度」，外加全课合计。
- **产出 2**：`课程交付/00_课程总览_索引.md` 的**自动索引区块**——以 `<!-- vcp:auto-index:begin -->` … `<!-- vcp:auto-index:end -->` 包裹，重跑幂等改写，**标记块外的人工内容一律保留**；文件不存在则新建，存在但无标记则**追加**（不覆盖）。配图数取磁盘实际计数（W5）。
- **为何不写 `pipeline_state.json`**：该文件由 runner 独占——每步执行前后都会用**内存态整体覆写**（`_save()`），脚本侧写入会被紧接着的一次保存覆盖，属竞态。故汇总落**脚本自有记录**，职责清晰、可重复生成。
- **覆盖范围**：`_work/*/` 下每个节目录一条记录；缺 `verify_report.json` 的节会在 `total.sections_without_verify` 中显式列出（不静默）。

## 6. 全量校验清单（交付前必做）

**机械项 = 6 项门禁**（`vcp.py verify` 自动执行；结果落 `verify_report.json`）。**硬项不达标 `exit 3` 阻断交付；软项（启发式判据）显式告警不阻断**——软项须逐条处置并在确认门说明。

| 门禁 | 内容 | 判据与级别 |
|---|---|---|
| **1 引用完整性** | 交付文档存在；修正版存在；截图引用零缺失；截图零冗余（无孤儿）；**纯文字页未被当截图引用**（`讲义截图_文字页替代/` 不得出现在引用里） | 全为硬项 |
| **2 命名规范与名实一致** | 文件名符合 `第NN节_图MM_描述.ext`；章号/图号**零填充一致**（无 1 位与 2 位混用）；无空格/特殊字符 | 硬项 |
| | 文件名关键词 vs 画面 OCR 文本一致（消费 `naming_report.json`，W10） | 软项 |
| **3 最佳截取核对** | 锚点漂移数 == 0（消费 `anchor_check.json`，W13） | 硬项 |
| | 锚点均有候选帧（无 `no_frame`） | 软项 |
| **4 配图覆盖** | 每个 ≥ `coverage_min_chars`（默认 200）字的 H3 知识点段至少 1 图（纯文字段除外，W7） | 软项 |
| **5 时间锚点下传** | 逐字稿有 `▶` 锚点时，交付文档内联 `▶` **不得为 0**（W1） | 硬项 |
| **6 记录链 / 备份链 / 切片 / 外发 / 渲染 / 索引** | 去边前原图备份齐全；切片文件全部存在；段数一致（磁盘 = CSV = 索引）；每段时长误差 <5s；工作记录链完整；**配图索引 ↔ 磁盘一致**（`illustration_index.json` 有效条目数 == `讲义截图/` 实际张数，且条目指向的文件都在，W5）；外发扫描已通过（`desen_gate==on` 时强制）；Markdown 交付物均已出 PDF | 硬项 |

**语义项**（`verify` 步带 `checkpoint: confirm`，由用户放行；Agent 驱动时须在确认点向用户求证）：

- [ ] **图文位置判据 A/B/C/D 全为 0**（E 类合法例外放行，见 §3.7）；配图三条标准（内容匹配 / 数量按需 / 密集合成）已满足。
- [ ] **纯文字页处置复核**：`slide_class.json` 判 `text_only` 且 `review_required=true` 的帧已逐张人眼确认（分类是建议不是裁判，§2.5）。

## 8. 跨平台注意事项（汇总）

- **Python 解释器路径**：macOS/Linux `<venv>/bin/python`；Windows `<venv>\Scripts\python.exe`；脚本内用 `sys.executable`。
- **路径分隔符**：一律 `pathlib.Path` / `os.path.join`，禁硬编码 `/`/`\`。
- **ffmpeg 二进制**：默认从**套件 venv** 的 `imageio_ffmpeg` 取（跨平台自动释放；设备采集/直播录制复用同一二进制）；四级探测链见 §0.3，`--param ffmpeg_bin` 可覆盖。
- **机械步一律 Python**：`tools/vcp.py` 不依赖 POSIX shell 方言，Windows 原生可用（历史 `uses.shell` 步骤已全部迁移，仅「录制兜底」类仍需 ffmpeg 本身）。
- **文件编码**：CSV `utf-8-sig`（Excel 友好）；JSON/Markdown `utf-8`。
- **中文路径**：三平台支持；Windows 旧工具链偶 GBK 问题，全程 `encoding='utf-8'`。
- **权限/沙箱**：批量依赖安装触发护栏需用户授权，不污染系统。
- **目录/产品图片识别**：长图自适应切块再 OCR；结果需与逐字稿核对校正（标红），不可直接信原始 OCR。
- **直播/设备采集**：录制直播须处理到"直播结束"（Ctrl-C/超时）；设备采集注意跨平台采集后端（macOS avfoundation / Windows dshow / Linux v4l2 / DeckLink）；录制产物默认不长期留存（合规，见 §0.6）。
- **工作记录复用**：重跑阶段前先读 `<WORK_REC>` 上游记录；勿重新转录/抽帧/解析时间戳/重新检测产品。`--resume` 自动跳过已完成步，`--step N` 定点重跑。

### 11.1 双文件分工

| 文件 | 位置 | 角色 |
|---|---|---|
| `workflow.json` | `workflows/video-to-content-pack/` | **可执行契约**（机器读）：trigger / params / requires / optional_capabilities / state_schema / steps[uses, reads, writes, checkpoint, when]。被 `kit workflow run` 加载 |

| `蓝本.md`（本文） | 同目录（随工作流分发，跨平台跨设备可复用） | **人类可读蓝本**（唯一权威内容来源）：各步骤实现细节、跨平台注意事项、踩坑记录、设计理由 |

同步规则：契约中的步骤语义、记录链 schema、触发词均以本文为据；**改流程先改本文，再同步契约与脚本**（frontmatter「预设元信息」段为同步锚点，`kit workflow check` 自检本文与契约是否脱节）。

### 11.2 执行模型（意图触发 → runner + Agent 协作）

1. **触发**：用户意图命中契约 `trigger.intent_keywords` → Agent 调 `kit workflow run video-to-content-pack --workspace <WORKSPACE> --param ...`。
2. **预检**：runner 加载契约，合并 params 默认值与 CLI 覆盖（**路径参数统一做 `~` 展开**）；`precheck` 步做参数/来源/ffmpeg/解释器自检，`preflight` 步跑 `kit doctor`。
3. **机械步**：`uses` 指向三类目标，由 runner 直接分发——
   - `{"kit": "<子命令>"}`：kit 内建（如 `doctor`）；
   - `{"component": "<cmd>", "args": [...]}`：**经 `cmd_run` 走组件分发**，从而继承「外发必扫 DESEN」闸门（v0.3.0 直连组件入口，会**绕过闸门**，已修）；
   - `{"script": "tools/vcp.py", "args": [...]}`：**工作流自带脚本**（跨平台纯 Python）；runner 注入 `OFFICE_KIT_ROOT` / `OFFICE_KIT_PY` / `OFFICE_KIT_WORKFLOW`，以工作流目录为 cwd，并对目标路径做**越界防护**。
   > 命令字符串统一走 `shlex` 切分——路径含空格或引号时不再被误判为 shell（v0.3.0 实测 `['extract', "'/tmp/a b.mp4'", …]` 带着字面引号下发，已修）。
4. **创作步**：`"executor": "agent"` 步骤（**7 个**：选帧 `frame_pick`、写作 `authoring`、配图 `illustrate`、文案 `copywriting`、目录 `catalog_acquire`、产品 `product_catalog`、裁切计划 `cut_plan`）由 **Agent 按本文对应章节执行**。runner 遇到此类步会**标记 `await_agent` 并暂停**（打印该步 desc 与 `step-done` 回填指引）；Agent 完成后执行 `kit workflow step-done video-to-content-pack <step_id> [<step_id> ...] --workspace <WORKSPACE>` 回填为 done（**支持一次多步回填**），再 `--resume` 续跑。runner 不重造创作逻辑。
   > v0.3.0 有 12 个 agent 步（去重、拼 ffmpeg 命令等机械活也交给了 Agent）→ v0.4.0 压到 **7 个**，减少 5 次 resume 往返。
5. **确认门**：`checkpoint: confirm` 对应本文「待确认门」模式（选帧/写作/配图/文案/目录/产品/裁切计划/校验放行）；CLI 交互挂起 `input()`，Agent 驱动时用 `--yes` 并自行在确认点向用户求证。
6. **续跑与定点重跑**：中断/确认暂停/agent 步回填后 `--resume` 从断点继续，已完成步自动跳过（对应 §0.4「一次计算、落盘复用」）；`--step N` 只跑某一步；`--dry-run` **只打印计划、不执行、不写状态**（v0.3.0 干跑会污染 `pipeline_state.json`，已修）。
7. **产物指纹**：每步完成时对该步 `writes` glob 命中的文件登记 **sha256**（`_fingerprint`），写入 `pipeline_state.json`，用于判断产物是否被改、是否需要重算。

### 11.4 降级矩阵与触发裁决

- **live/capture 降级矩阵**：原生路径**已生效**（2026-09-03 已同步组件，见 §10）——`source=live`/`device` 直连 `extract --live/--device`；`source=live_fallback`/`device_fallback` 保留为录制完整性兜底（边转失败不影响录制），降级录制由 `vcp.py` 用套件 venv 的 ffmpeg 承担。
- **触发歧义裁决**：多步/交付物形态指定（出讲义/切片/文案等组合意图）→ 优先本工作流；单一动作（仅转录、仅 OCR、仅摘要）→ 仍走 `extract` / `summarize` 单命令。Agent 按意图复杂度裁决，不确定时先问用户。
- **契约自检**：`kit workflow check video-to-content-pack` —— 6 类校验：① 步骤齐全且 `uses` 与 `executor: agent` 互斥；② 每个 `when` 引用的参数已在 `params` 声明（只解析 `k==v` / `k not in …` 的**左侧键**，不误伤右侧值）；③ `uses` 合法性（`kit` 子命令白名单、`component` 在 `requires.components` 内、`script` 目标**存在且不越出工作流目录**）；④ `state_schema.records` 的 owner/consumers 都是真实 step id；⑤ `blueprint_doc` 存在；⑥ **蓝本 frontmatter 版本 = 契约 `version`**。**改流程后必跑**。
