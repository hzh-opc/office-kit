# 配图阶段通用规范（illustration-spec）

> 隶属：`office-kit` 工作流 **`video-to-content-pack`**（视频转内容包）。
> 定位：在 `frame_pick`（选帧与命名归位）→ `crop_shots`（去边）→ `authoring`（交付文档 / 讲义写作，蓝本 §3）**之后**、`verify`（全量校验）之前，作为一个 **`executor: agent` 创作步**（`illustrate`）执行——把已去边的截图，按内容匹配插入交付文档的对应位置。
> 本文是**通用、可跨项目复用**的配图方法。**项目专属**的命名规则、源视频路径、本地脚本、调整历史等一律不在此硬编码，见各项目自身文档（如《超凡手机摄影》的 `配图规范与调整总结.md`、《细味情感拍人像·安菲菲》的 `work/讲义生成工作流手册.md`）。已落地验证项目：超凡手机摄影（视频录屏课）、细味情感拍人像·安菲菲（语音+配图聊天回放课）——两类形态均验证本规范可复用。

---

## 一、三条核心标准（判定配图是否到位）

| 标准 | 含义 | 达标判据 |
|---|---|---|
| ① 内容匹配 | 配图须为文字内容最贴切的截图 | 图与紧邻文字语义相似度最高；**无错配**（图讲 A、文讲 B） |
| ② 数量按需 | 配图数量由内容密度与展示需求决定，不多不少 | 每个点名 / 列举的作品、每个技法示范、每个对比项至少 1 图；密集段可合成折叠，不堆无关图 |
| ③ 多处合成 | 同一段文字配图较多时，裁切 / 合成一张配图 | 连续单图 ≥3 且同主题 → 合成为网格图（保持统一比例），避免版面碎裂 |

---

## 二、图文位置判据（A / B / C / D / E 五类）

**总原则**：正文在前，配图紧跟其对应文字之后。

- **A 类 · 真错位（硬违例）**：图出现在完全不相关的章节 / 小节。→ 必须修。
- **B 类 · 多图堆叠（硬违例）**：多条 bullet 之后堆多张图、或图夹在两条 bullet 之间。→ 必须修（图应紧随其归属文字）。
- **C 类 · 图先于文（硬违例）**：图排在其说明文字之前，读者会把图误归给上文。→ 必须修。
- **D 类 · 裸图堆叠（硬违例）**：图中线紧邻的前一个非空块也是图片，且本图说明并不紧随其后 → 读者把两张图一并归给上文。→ 必须修。
- **E 类 · 合法例外**（以下形态不算违例，体检应放行）：
  - 小标题 → 例图 → 说明（**节首例图**）；
  - **一条** bullet 并列多例、图紧随该条之后（**一对多**）；
  - 成组对比图（如「打光前 / 打光后」）；
  - 作品罗列段（每张作品图紧随其名）。

> 判据实现参考：`audit_image_before_text.py`（D 类硬违例扫描 + E 类候选枚举）；`check_image_order.py`（A / B / C 三类，A 必须为 0）。
> **相似度只是筛子不是裁判**：高相似度候选仍需人工 / VLM 核对「最贴切」，避免机械命中却错配。

## 三、配图七步闭环（执行法）

1. **通读小节**：按 `##` / `###` 切分，列出「点名作品 / 技法示范 / 对比项」等需图锚点。
2. **定位画面**：回看源视频 / 逐字稿，给每个锚点定抽帧时刻；若上游 `frame_pick` / `crop_shots` 已有选帧与去边产物，**直接复用，不重抽**。
3. **批量核验**：把候选帧 `montage` 拼成一张图，人工 / VLM 核对「最贴切」且非错配。
4. **插入**：用插入工具把图写到其归属文字紧后；图前一句宜有「这张 / 那张 / 比如」等指称，形成「引导 → 图 → 说明」节奏。
5. **规范化**：图片行上下空行符合本库版式（注意「图后双空行」可能是既有合法版式，勿当脏数据清）。
6. **重编号**：按「编号 = 文档出现顺序」重排受影响章，保证同章编号递增、无跳号、无重复引用。
7. **五项自检**：引用 / 缺失 / 孤儿 / 重复 / 编号递增 全部为 0；再跑图文顺序体检（A / B / C 为 0）与图文位置体检（D 为 0、E 类合法）。

---

## 四、终检清单（交付前必过）

- [ ] 引用总数 == 图片文件数（无缺失、无孤儿）
- [ ] 同章内编号严格递增、无重复引用
- [ ] `check_image_order`：A 真错位 / B 多图堆叠 / C 图先于文 == 0
- [ ] 图文位置体检：D 裸图堆叠 == 0；E 类候选均为合法例外
- [ ] 非合成图统一比例（如 16:9）；合成图（网格）宽 ≥ 高且尺寸受控
- [ ] 标准①无错配、标准②无「点名无图」、标准③连续同主题单图已合成
- [ ] **布局体检（verify_layout）**：分离块 == 0 / 未引用 == 0 / 连续图行 ≤ 2（见「九」）
- [ ] **渲染层换行**：源 .md 无硬换行（≤40 字 + 两空格 `<br>`），换行交给渲染层（见「八」）

## 五、与上下游的关系

- **上游**：`index_records`（帧清单 + MAD 去重）/ `frames_ocr`（画面文字）产出帧数据，`frame_pick`（选帧与命名归位）、`crop_shots`（去边）产出可用截图；`authoring` 产出带锚点的交付文档。
- **本阶段**：只做「选最贴切帧 + 插入 + 位置正确 + 多处合成」，**不改写文档正文、不重抽帧**。
- **下游**：`verify` 全量校验会把配图引用纳入「截图引用零缺失 / 小节一致性」检查。

> **已契约化（2026-09-17；2026-09-22 复核同步）**：`illustrate` 步已正式写入 `workflow.json`（`authoring` 之后、`copywriting` 与 `verify` 之前；`executor: agent` + `checkpoint: confirm`；`writes: ["illustration_index.json"]`），runner 强制本阶段。`state_schema.records` 已登记 `illustration_index.json`（owner=`illustrate`，consumers=[`verify`]）。蓝本 §3.7 已载「交付文档配图」小节——**UTF-8 编码、随工作流同包分发、可直接按字面安全编辑**；此前「GBK 编码 / 单独仓库 / 待同步」的表述已失效。

## 六、常见失效模式与预防（来自实战复盘）

> 跨项目通用。以下失效模式在多个项目反复出现（已验证：超凡手机摄影、细味情感拍人像·安菲菲），故抽离为工作流级预防门，写进「三、配图七步闭环」的 2.1–2.9。项目专属案例见各项目自身文档。

| # | 失效模式 | 典型表现 | 根因 | 前置预防（落到 2.1–2.9 自检） |
|---|---|---|---|---|
| 1 | 缺图·罗列漏筛 | 作品欣赏 / 案例罗列型章节，正文一行列多个具体作品名却无图 | 筛查只匹配「这张 / 那张」指代词，漏掉「并列罗列」「例 N」信号 | 标准② 同时卡三类信号：指代词 / 一行多作品名 / 例 N 结构；每章收尾做「正文点名作品数 vs 该节配图数」计数比对 |
| 2 | 缺图·计数噪声 | 段落级初筛命中大量「这一张照片」口语泛指，虚高 | 判据卡了领域名词而非「具体指代一张可描述照片」 | bullet 级「指称数 − 配图数 ≥ 2」可信、删完即归零；段落级仅初筛，必须逐条人眼确认 |
| 3 | 图文位置错位 | 图在多条 bullet 后堆叠 / 夹在 bullet 间 / 图在文前 / 两图直接堆叠中间无字（D 类） | 规范只管「内容对」没管「位置对」 | 跑 `check_image_order`（A/B/C=0）+ `audit_image_before_text`（**D=0**）；E 类合法例外白名单（节首例图 / 一对多 / 配对图组 / 作品罗列） |
| 4 | 内容错配·抓错帧 | 按时间戳抓到下一话题幻灯片；作品图抓成取景界面帧；抓错小节内次级重点 | 抓帧前未读正文定落点；未区分「作品 / 概念 / 界面」三类帧 | 抓前先读正文明确「最想让读者看到什么」：作品/效果→成片全屏帧，概念/方法→带标注帧，App 操作→界面帧即内容；抓后逐张核验「画面=文件名=图注=正文」四一致 |
| 5 | 内容错配·位置致否定 | 图放错小节，图注被紧随文字「这张照片不是…」反向否定 | 只看「内容对」没看「位置对 + 上下文自洽」 | 检查图注与上下句自洽；留意转折句（「不是 / 恰恰相反 / 其实并不」）常否定上一张图 |
| 6 | 技术规格·分辨率/黑边 | 低分辨率图混入；黑边阈值过松把暗调暗部当黑边裁掉；横向裁切上限过窄裁不净 | 判定阈值未经真实暗调照片校准；多脚本判定不一致 | 非合成图统一比例（如 16:9）；黑边铁律「近纯黑 <12 且覆盖率 ≥99.5%」，横向 ≤40% / 纵向 ≤22%，裁后单维 ≥原 35%；所有裁边脚本共用同一判定 |
| 7 | 路径/编号硬伤 | 引用双前缀全失效；编号重排正则整体 ±1 致全章错位；管道 `&&` 清理误删；幂等判据漏算新增项 | 路径校验只比 basename；重排用正则整体偏移；清理与抓帧串在管道 | 路径校验比**完整相对路径**；编号按出现位置重写为位置序号；抓帧与清理分开执行；可重跑脚本幂等判据把新增项算进去 |
| 8 | OCR 一致性·OOM | 循环内反复推理内存累积，~30 张被 OOM 静默杀，表象卡死 | 单进程内反复初始化推理引擎内存泄漏 | 每图独立子进程（subprocess-per-image）+ 编排器断点续跑 + 单图超时；一致性比对用独立脚本 |

**通用铁律**：
- **相似度是筛子不是裁判**——任何相似度候选必须人眼 / VLM 核对上下文。
- **改完必须复核**：图行前后是否粘连、引用与文件是否一一对应、编号是否递增。
- **确认组件实际运行解释器**再下「缺依赖」结论——本工作流的 OCR / 转录 / 抽帧 / 排版一律在**套件虚拟环境 `~/office-kit/.venv`** 内解析（`envs/default` 不含组件依赖；media 环境自 2026-09-22 起不再是必需项）。
- **与工作流默认去边实现的关系**：`tools/vcp.py crop` 采用**更保守的通用护栏**——保留 ≥55% 面积、单边裁掉 ≤200px、边缘须近纯色暗底（std≤20）；上表失效模式 ⑥ 的百分比阈值来自《超凡手机摄影》暗调照片场景，属**项目级更严格校准，不下沉到通用脚本**。通用脚本保证「不误裁」，项目如需更激进判据可另挂项目脚本。

## 七、配图四原则（存储与呈现层 · 来自「细味情感拍人像·安菲菲」实战）

与「一、三条核心标准」（选哪张 / 选几张 / 是否合成）互补——本原则管「图放哪、多大、是否独立建索引」：

1. **图随文**：配图紧跟其归属文字内联，不挪到文末或独立堆。
2. **小图入讲义**：正文内联用缩略图（最长边 ≤ 900px），大图原文件留独立目录供查阅，避免讲义文件膨胀、加载慢。
3. **大图留独立索引**：成组 / 大尺寸图建独立「配图索引」文件（按正文实际内联顺序重建），正文只留索引引用，不把几十张图全铺进正文。
4. **组合消堆砌**：相邻同主题多图（≥3）合成为网格图（见标准③），避免版面碎裂与连续图行堆叠（呼应 D 类 / 布局校验）。

> 落地自检：内联后跑 `verify_layout`——分离块 == 0 / 未引用 == 0 / 连续图行 ≤ 2（见「九」）。

## 八、渲染与导出纪律（源文件零硬换行 · 方案 C）

- **总纲**：源 .md 保持「干净逻辑段落」，所有排版 / 换行 / 缩放问题都在**渲染层**解决，绝不回写硬换行污染源文件。
- **禁止**：用「≤40 字 + 两空格 `<br>`」硬换行重排源文件修预览（方案 B）——会在窄窗碎片化、污染 GitHub / VS Code 渲染，且不可逆地破坏源。
- **正确**：编辑视图用 `soft_wrap`（仅改显示，不改源）；分享 / 打印走统一 HTML（CJK 避头尾：`line-break:strict; text-wrap:pretty`，自适应任意宽度）；PDF 用浏览器 Cmd/Ctrl+P（不从源文件另造排版）。
- **红线**：源文件无硬换行是交付物红线——任何「预览不对」先改渲染层 / 模板，不碰源段落。

## 九、布局校验标准（verify_layout · 可跨项目复用）

三项硬指标（全课通过方可交付），与「二、图文位置判据」互补：判据管「图与紧邻文字的位置关系」（A/B/C/D/E），本标准管「整篇配图的结构健康度」。

| 指标 | 含义 | 达标 |
|---|---|---|
| 分离块 == 0 | 没有图片被甩到与其说明文字无关的块 | 图均在内联归属文字附近 |
| 未引用 == 0 | 索引 / 独立配图文件中的图，正文必须实际内联引用 | 防「只在索引出现、正文漏嵌」 |
| 连续图行 ≤ 2 | 同一处不得连续堆叠超过 2 张图 | 超则合并 / 配文拆分（呼应标准③与 D 类） |

> 关联失效模式：见「六」① 缺图（未引用=0 反向校验）、③ 图文位置错位（连续图行 / 分离块）。

## 十、操作红线（Agent 执行本阶段前必读）

> 来自两个项目反复踩坑，属工作流级硬约束，违反会污染源文件或静默丢改。

1. **源文件零硬换行**（见「八」）——方案 B 已回滚，勿再用。
2. **同文件多 Edit 必须串行**——一次一条、逐条确认，改完 `grep` 复核；并行会静默只落部分。
3. **大改前必备份**——结构性改动前 `cp -r` 至备份目录。
4. **子图说明以目检为准**——不照抄旧 alt（旧 alt 本身可能误）。
5. **示意图 / 光位图合成**——必须 `--fit height --cell-h --bg #f3f3f3`（统一行高、各图保宽、浅灰填悬空），勿统一宽度缩放破坏竖向空间语义。
6. **跨课重复素材保留不动**；仅同课内 0.0 像素差才去重（指纹去重）。
7. **OCR / 批量推理一律 subprocess-per-image + 断点续跑**——防内存累积 OOM 静默杀。
