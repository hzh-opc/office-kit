# 版面美学观 · 侯捷《Word 排版艺术》提炼

> 来源：侯捷《Word 排版艺术》（电子工业出版社，2004，ISBN 9787121004216，豆瓣 8.6）。
> 书中核心哲学源自作者自序「艺术与工程」「不带 dirty work 的工程，就是一种艺术」「我要自己排版，完全掌控读者将来在纸件上看到的每一样东西」；设计四原则（CRAP）由 Robin Williams《The Non-Designer's Design Book》提出，侯捷将其系统引入中文 Word 文档语境。中文混排与标点细节参考业界中文排版规范（justfont 避头尾、中文排版核心规范等）。

---

## 一、核心哲学（态度论）

1. **艺术与工程交汇**：排版不是纯技术，也不是纯艺术；「不带 dirty work 的工程，就是一种艺术」。
2. **排版是态度**：对作品最终形貌的完全掌控——每个字、每张图的大小、颜色、粗细、位置都在自己手里。
3. **工具服务于创作**：掌握 Word 是为了「专注于内容创作，不为劳役所苦」，把人从繁琐格式调整中解放出来。
4. **样式（Style）是理论基石**：一次定义、全局复用，是效率与一致性的根源；手动局部格式是脏活与风险的来源。
5. **自动化是规模化关键**：章节自动编号、图表自动编号、目录、索引、交叉引用、页眉页脚均应力求自动生成。
6. **输出一致性**：Word + Acrobat 制作 PDF，保证文档在不同设备上阅读形态一致（侯捷推崇的组合）。

---

## 二、七大美学原则（体系）

基于 Robin Williams 的 CRAP 四原则（对比 / 重复 / 对齐 / 亲密性），扩展为中文 Word 文档的「七大原则」。

### 1. 对齐 Alignment
- 任何元素都不随意摆放；每一项都应当与页面上另一项存在某种视觉联系。
- 中文正文：两端对齐（justify）使版心左右边缘整齐。
- 中英混排或含长英文单词：左对齐更安全，避免两端对齐把单词间距拉出「河流」（river）效应。
- 标题可居中（正式）或左对齐（现代）；避免同一版面混用多种对齐方式。
- **视觉对齐优先于物理对齐**：物理对齐看着没对齐时，调到视觉对齐。

### 2. 对比 Contrast
- 如果两个元素不完全相同，就让它**截然不同**，制造视觉焦点与层级。
- 手段：字号对比（标题↔正文强烈大小差）、字重对比（粗↔细）、颜色对比、空间对比（大留白↔密集文字）。
- 切忌「似是而非」的相似——要么相同，要么迥异。

### 3. 亲密性 Proximity
- 相关内容靠近成组，无关内容以留白区隔。
- 标题与副标题靠近；图与图注相邻；时间 / 地点 / 主办归为一组。
- 仅改变间距，就能改变读者对信息分组的认知。

### 4. 重复 Repetition
- 视觉元素（字体、颜色、线宽、间距、编号格式）在全文重复，建立统一与节奏感。
- 用「样式」固化重复；过度重复会疲劳，需在多样性中实现统一。

### 5. 留白 White Space
- 给版面「呼吸感」，是最高级的对齐与分组工具。
- 页边距、段间距、行距、图文间距都服务于留白。
- 留白不是浪费，而是引导阅读的结构手段。

### 6. 节制 Restraint
- 少即多（less is more）。
- 全文字体 ≤ 3 种；颜色 ≤ 主色 + 2~3 辅助色。
- 慎用斜体、下划线、阴影、艺术字、过多色彩；强调靠对比与重复，不靠堆特效。

### 7. 中英文混排和谐 CJK Harmony（中文文档专属）
- 字体搭配：正文 思源宋体 + Noto Serif（印刷 / 正式）；思源黑体 + Noto Sans（屏幕 / 现代）。
- 字号：英文比中文小 1~2pt，视觉才平衡（英文笔画简单，同字号显小）。
- 间距：中英文之间、中文与数字之间加半角空格。
- 标点：中文用全角、英文用半角，不混用；开启「避头尾」与「标点悬挂」。
- 衬线 vs 无衬线：标题用无衬线（思源黑体）突出；正文用衬线（思源宋体）利阅读。
- **字体版权（重要）**：本文档默认使用**开源可商用**字体——思源宋体 / 思源黑体（SIL OFL 1.1）、Noto Serif / Noto Sans / Noto CJK（SIL OFL 1.1）、霞鹜文楷（SIL OFL 1.1）、文泉驿（GPL + font exception）。**不使用**宋体 / 黑体 / 微软雅黑 / 楷体 / 苹方 / Arial / Times New Roman / Consolas 等商业系统字体，以规避版权纠纷。详见文末「字体版权与开源字体」。

## 四、排版自查清单（交付前逐条核对）

- [ ] 全文是否只用「样式」定义格式（无手动局部格式）？
- [ ] 标题层级是否清晰（≤4 级）且可自动生成目录？
- [ ] 对齐方式是否统一（无多种对齐混用）？
- [ ] 是否有清晰视觉焦点（对比）？
- [ ] 相关信息是否成组（亲密性）？
- [ ] 重复元素（字体 / 颜色 / 编号格式）是否一致？
- [ ] 留白是否充足（页边距、段距、行距）？
- [ ] 字体是否 ≤3 种、颜色是否克制？
- [ ] 中英文混排：字号、间距、标点是否处理？
- [ ] 是否启用避头尾、标点悬挂？
- [ ] 编号 / 目录 / 页码 / 页眉是否自动生成（非手填）？
- [ ] 图文是否有题注、编号、适当间距？
- [ ] 打印 / PDF 输出前是否关闭「编辑标记」？

## 五、反模式（务必避免）

- 用空格代替首行缩进 / 对齐。
- 手动输入编号、目录、页码。
- 全文居中对齐（初学者陷阱，乏味且缺设计感）。
- 字体 / 颜色过载（>3 字体、花哨配色）。
- 滥用斜体、下划线、阴影、艺术字。
- 两端对齐导致英文「河流」效应。
- 中文使用斜体（中文无斜体概念，强调用加粗替代）。
- 标点混用（中文全角与英文半角混排不分）。

## 六、Word 实现要点（工程侧）

- **样式**：基准为正文；标题样式链接「多级列表」实现自动编号；改一处即全局更新。
- **分节**：封面无页码、目录罗马数字、正文阿拉伯数字；插「下一页分节符」并取消「链接到前一条页眉」。
- **域**：交叉引用、题注、目录、索引均用域自动生成与更新。
- **图文**：图片居中 + 适当间距；加题注并通过交叉引用引用。
- **表格**：按长短分两种跨页策略——
  - 长表格（≥5 行或多页）：开启「标题行重复」(`w:tblHeader`) + 取消「允许跨页断行」(`w:cantSplit`)，避免单行在页中间被截断、续页丢失表头。
  - 短表格（1~2 屏可容纳）：整表「保持在一起」——对表内**所有段落**设 `w:keepNext`+`w:keepLines`，并令其**前一段（标题/引导语）与本表同页**；**不**逐行禁断。此法人为整表作为一个块落在同一页，比逐行 cantSplit 更自然。
- **输出**：Word → Acrobat PDF，保证跨设备一致；长文档（≥3 页加页码，≥5 页加目录）。

## 七、触发与适用场景

本规范适用于以下任务，应在产出前主动套用：
- 撰写 / 排版 Word 文档、报告、论文、说明书、方案，以及手账 / 笔记 / 小开本印刷物。
- 制作 PPT / 幻灯片（中文内容、16:9 演示）。
- 搭建网页 / HTML / 响应式页面（移动优先、多终端适配）。
- 生成 PDF、长文档、技术文档、出版物料，以及名片 / 明信片 / 手账页等多纸型。
- 任何「让输出更专业、更易读、跨终端一致」的版式优化请求。

## 九、网页排版原则（响应式）

网页是「流动版心」，核心是用流式单位与断点适配任意宽度。

- **版心宽度**：正文容器 `max-width: 65~75ch`（中文每行 35~45 字），水平居中；避免长行伤读。
- **流式字号**：`font-size: clamp(1rem, 0.9rem + 0.4vw, 1.125rem)`，根字号 16px 起；标题用更大 clamp 阶梯。
- **断点（移动优先）**：先写手机样式，再 `min-width` 增强；常用 手机 `<640px`、平板 `640~1024px`、桌面 `>1024px`（768 / 1024 两道）。
- **行距与段距**：屏幕阅读行距 `1.6~1.8`；段间距 `1~1.5em`，比印刷松。
- **层级对比**：字号阶梯 ≥1.5:1（如 16→24→36）；用字重 / 颜色制造焦点。
- **颜色对比**：正文与背景达 WCAG AA（≥4.5:1）；用 CSS 变量管理主色 + 辅助色。
- **深色模式**：`@media (prefers-color-scheme: dark)` 切换变量；避免纯黑底纯白字（刺眼）。
- **栅格**：CSS Grid `repeat(auto-fit, minmax(280px, 1fr))` 或 Flexbox；列数随宽自适应。
- **可达性**：焦点态可见、语义标签、替代文本；`prefers-reduced-motion` 关闭动效。

## 十、幻灯片排版原则

幻灯片是「远距阅读」，字要大、信息要少、对比要强。

- **画幅**：默认 16:9（13.333×7.5in = 254×190.5mm）；老投影 4:3；超宽屏 16:10。
- **字号**：标题 36~44pt，正文 24~28pt，**最小 ≥18pt**（后排可读）；讲稿放「备注」而非堆屏。
- **信息密度**：每页一个观点；正文 ≤6 行、每行 ≤30 字；用要点而非段落。
- **安全区**：内容距边缘 ≥0.5in（约 12.7mm），避免被投影 / 投屏裁切。
- **对齐与网格**：左对齐为主，元素对齐到隐式网格；避免居中堆砌。
- **对比**：深 / 浅背景 + 单一强调色；背景勿用复杂图片喧宾夺主。
- **图片**：统一边框或满幅，`object-fit: cover` 不变形；图表用大号、去冗余网格线。
- **动效**：克制，仅用于分步揭示；尊重 `prefers-reduced-motion`。

## 十一、多终端显示优化（平板 / 手机）

同一份内容要在手机、平板、桌面都有好体验，靠「移动优先 + 流式单位 + 响应式资源」。

- **视口**：`<meta name="viewport" content="width=device-width, initial-scale=1">` 必备。
- **移动优先**：先写手机基础样式，再用 `min-width` 断点增强；不写死 `px` 宽度。
- **触控目标**：按钮 / 可点元素 ≥44×44px（Apple HIG）/ 48dp（Material），间距充足防误触。
- **流式排版**：标题 / 正文用 `clamp()` 在 320~1440px 间平滑缩放，不靠多套固定值。
- **安全区**：`padding: env(safe-area-inset-*)` 适配刘海 / 圆角 / 底部手势条。
- **图片自适应**：`srcset`+`sizes` 按 DPR / 视口加载；`max-width:100%; height:auto` 防溢出。
- **可读行宽**：移动端正文每行 30~40 汉字，过长换行、过短频繁折行都伤读。
- **系统字体栈**：`"Source Han Sans SC", "Noto Sans CJK SC", -apple-system, sans-serif` 开源优先、免下载、渲染快、跨端一致。
- **减少动效**：`@media (prefers-reduced-motion: reduce){ *{ animation:none; transition:none } }`。
- **对比与焦点**：文字对比达标；键盘 / 焦点态明显，满足可达性。

## 十二、腾讯文档云端路径（能力边界与落地）

当用户要求把成果直接落到腾讯文档（`docs.qq.com`）云端时，走 `tencent-docs` 插件的 `doc-mcp` 引擎。该路径与本地 `python-docx` 模型不同：云端用「内容 + 范围属性」模型，**无 Word「样式」画廊**，因此「一次定义全局复用」需改为「统一模板 / 重复调用」维持一致。以下结论均经实跑 `doc-mcp` 校验。

### 落地步骤

1. **环境就绪**：插件鉴权依赖宿主（Workbuddy）注入的腾讯文档票据，`python3 tencentdocs.py tdoc_init` 返回 `READY` 方可调用。
2. **创建**：`doc-mcp.create_with_markdown`，参数名为 **`base64_markdown`**（不是 `markdown`），值为 Markdown 的 base64 编码；`title` 可选。支持标题 / 列表 / 表格 / 任务清单（`- [ ]`）。
3. **字体 / 颜色 / 字号（中英文混排核心）**：`doc-mcp.update_text_property`，`ranges=[{begin,end}]` 为字符偏移，`property` 支持 `font_family`（可填 `思源宋体` / `思源黑体` / `Noto Sans`）、`color`（6 位十六进制无 `#`）、`font_size`（磅）、`bold` 等。
   - ⚠️ **range 终点必须落在段内文本字符，不能停在段落分隔符**（否则报 `should have rpr`）；取 `begin=节点 start_index`、`end=下一节点 start_index − 1`。
4. **表格美化**：`doc-mcp.set_table_properties`，`idx` 取表内任意单元格字符偏移；可设 `borders`、`alignment`、`cell_margin`、按 `first_row` / `band_row_even` 等 `condition` 染色的 `cell_fills`。
5. **富文本提示条**：`doc-mcp.insert_html_content`，`idx` 须为段落起始位置；支持 `<p>/<h1..6>/<b>/<i>/<u>/<span style>/<table>/<ul>/<ol>`；**不支持** `<style>/<script>` 与 CSS 布局属性（position/float/flex/grid）。

### 能力边界（相比本地 Word / python-docx 的疏漏）

- ❌ **表格跨页保护**：无 `cantSplit` / `tblHeader`（标题行重复）对应 API；长表跨页仍可能被截断、续页丢表头。→ 规避：表格尽量短、或回腾讯文档网页端手动开「标题行重复」；设计时避免单表跨页。
- ❌ **避头尾 / 标点悬挂**：`update_text_property` 无此字段，无法强制。→ 依赖腾讯文档默认 CJK 行为。
- ❌ **首行缩进特殊格式（2 字符）**：无缩进 / 特殊格式字段，Markdown 亦不可表达。→ 接受默认或权衡使用全角空格（不推荐）。
- ❌ **Word「样式」画廊**：云端无样式概念，`update_text_property` 为逐范围手动；「一次定义全局复用」需靠统一 HTML 模板或重复调用维持一致。
- ⚠️ **自动目录 / 多级列表编号**：可 `insert_numbering` 建列表、`get_outline` 读大纲，但无自动 TOC 域；编号需逐处触发。
- ⚠️ **分节 / 页码格式（罗马 vs 阿拉伯）**：`set_page_number` 有限，复杂页眉页脚难精控。

### 结论

七大原则中 **对齐 / 对比 / 亲密性 / 重复 / 留白 / 节制 / 中英文混排（字体层面）** 在云端均可落地（字体、颜色、表格边框底色、HTML 提示条均已实跑成功）；唯 **跨页保护、避头尾、首行缩进特殊格式、样式画廊** 四类 Word 专属能力云端暂缺，需以「规避设计 + 网页端手动补」兜底。可复用 helper：`scripts/build_tencent_doc.py`。

## 十三、Markdown → PDF 直转路径（轻量）

当用户手里只有 Markdown 源（无 docx 模板），又想直接得到排版良好的中文 PDF 时，走 `scripts/build_md_pdf.py` 直转路径，**不经过 docx 中间产物**。该路径同样遵循本规范的七大原则与具体参数，但做了几项适配：

- **字体配对**：与 docx→PDF 路径一致——正文 思源宋体（衬线，CJK）+ 标题 思源黑体（无衬线，CJKH）；西文回退 Times-Roman（reportlab Base-14 标准字体）。字体探测「开源优先」：思源宋体/黑体、Noto CJK、文泉驿（均 SIL OFL / GPL+font exception 可商用）；系统自带字体（Songti/STHeiti/SimSun/SimHei）仅作最后兜底并打印版权告警。
- **正文排版**：A4、左右页边距 2.5cm、上下 2.5/2.2cm；行距 1.5 倍（11pt/16.5pt）；首行缩进 2 字符（22pt）；**正文左对齐（TA_LEFT）**——Markdown 几乎必含中英混排，两端对齐会拉出"河流"效应（字间距被强行撑满行宽），违反美学规范第七条。纯中文段落同样左对齐（Markdown 来源的现实决定）。
- **标题层级**：H1 18pt 深蓝 + 1.2pt 蓝色横线；H2 15pt 深蓝 + 0.6pt 浅蓝细线；H3 13pt 深绿（与 H1/H2 深蓝形成层级色彩对比）。
- **主题色**：与 docx→PDF 统一——NAVY `#1F4E79`（深蓝主色）、H2 `#23527C`、H3 `#2F6B3E`（深绿层级）、单一强调深红 `#9E2B25`（行内代码 / 强调）。
- **表格跨页保护**：长表（>4 行）`repeatRows=1` 续页重复表头；短表 `KeepTogether` 整表保持一页。表头深蓝底白字、斑马纹 `#F3F7FB`、网格线 `#9AA7B4`。
- **Markdown 能力**：标题（H1~H3）、**加粗 / *斜体* / ~~删除线~~、行内代码 `` `code` ``（纯 ASCII Courier + 强调色；含中文 CJK + 强调色）、无序 / 有序 / 任务列表（`- [ ]` / `- [x]`，完成项用 `☑`/深绿）、代码块（``` 围栏 + 浅灰 `#F4F6F8` 背景 + 等宽视觉 + lang 标注）、本地相对路径图片（按版心宽度等比缩放、居中、缺失时降级提示）、链接（保留 text 去掉 URL，PDF 不可点击）、引用 `> `、分隔线 `---`、表格（自动估算列宽 + MIN 44pt 兜底）。
- **封面（可关）**：默认生成封面页——大号深蓝标题 + 可选副标题 + 深蓝短分隔线 + 生成日期 + 作者；`--no-cover` 直接从正文起。
- **跨平台**：stdout 统一 UTF-8 避免 Windows GBK 控制台对 emoji/生僻字报错；`detect_fonts` 开源优先候选路径覆盖（思源 / Noto CJK / 文泉驿，系统字体兜底）。

**两种 PDF 路径的取舍**：
- 先有 Markdown 源、需要快速直转、且对"与 docx 页面像素级一致"无要求 → `build_md_pdf.py`（纯 Python reportlab，无引擎依赖，零外部工具）。
- 已在做《版面美学观》docx 交付、或必须"PDF 页面与 Word 文档完全一致" → `build_pdf.py`（docx→PDF，引擎链 LibreOffice > docx2pdf > WPS > reportlab 兜底）。

## 十四、字体版权与开源字体

> 本技能**默认全部使用开源可商用字体**，不内置、不嵌入任何商业系统字体，以规避版权纠纷。以下为完整说明与安装指引。

### 字体映射（原商业字体 → 开源替代）

| 角色 | 原商业字体（已弃用） | 开源替代 | 许可 |
|---|---|---|---|
| 中文衬线正文 | 宋体 / SimSun / Songti | **思源宋体**（Source Han Serif SC） | SIL OFL 1.1 |
| 中文无衬线标题 | 黑体 / SimHei / STHeiti / 微软雅黑 | **思源黑体**（Source Han Sans SC） | SIL OFL 1.1 |
| 中文楷体（装饰） | 楷体 / KaiTi | **霞鹜文楷**（LXGW WenKai） | SIL OFL 1.1 |
| 西文衬线 | Times New Roman | **Noto Serif** | SIL OFL 1.1 |
| 西文无衬线 | Arial / Helvetica | **Noto Sans** | SIL OFL 1.1 |
| 等宽（代码） | Consolas / Courier | **DejaVu Sans Mono** | Bitstream Vera + public domain |
| 兜底中文字体 | — | **文泉驿正黑**（WenQuanYi Zen Hei） | GPL + font exception |

> 注：思源宋体 / 思源黑体与 Google 的 Noto Serif CJK / Noto Sans CJK **是同一套字体**（Adobe 与 Google 联合开发，字形一致，仅命名与打包不同），两者均 SIL OFL 1.1 许可，可自由商用、再分发、修改。

### 为什么必须改

- **PDF 嵌入是高风险点**：`build_md_pdf.py` / `build_pdf.py` 的 reportlab 兜底路径会把字体**子集嵌入**到 PDF 中。系统自带字体（macOS 的 Songti / STHeiti、Windows 的 SimSun / SimHei）许可通常**限制嵌入或仅允许打印预览**，用于商用分发的 PDF 存在版权风险。
- **docx / pptx / html / 腾讯文档**只写「字体名」、不携带字体文件，风险低；但为彻底规避并保证跨平台一致，同样统一为开源字体名。
- 脚本已实现「**开源优先探测**」：检测到思源 / Noto CJK / 文泉驿即使用；未检测到才回退系统字体，并**打印明确的版权告警**。

### 安装开源字体

| 平台 | 命令 / 方式 |
|---|---|
| macOS | `brew install --cask font-source-han-serif-sc font-source-han-sans-sc`（思源宋体 / 黑体） |
| Linux | `sudo apt install fonts-noto-cjk`（Noto CJK，含宋体 / 黑体） |
| Windows | 从 [Adobe 思源宋体](https://github.com/adobe-fonts/source-han-serif/releases) 与 [Adobe 思源黑体](https://github.com/adobe-fonts/source-han-sans/releases) 下载 OTF，双击安装 |

> 安装后重跑脚本即可自动命中开源字体；无需改动任何代码。
