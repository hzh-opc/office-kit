# desen-stop：从「文件分发」到「平台启用」操作指引

> 适用范围：本机或任何新机器，`git clone` + `./bootstrap.sh` 已完成（或已手动把
> `hooks/desen-stop/` 分发到 `~/.workbuddy/hooks/desen-stop/`）之后。
> 目的：让 desen-stop 的 Stop Hook 真正被 WorkBuddy 加载执行（而不只是文件就位）。

---

## 0. 一句话结论

启用分**三段**，缺一不可：

1. **文件分发** —— `bootstrap.sh` 第 5 步（把插件包复制到 `~/.workbuddy/hooks/desen-stop/`）；
2. **市场目录** —— `bootstrap.sh` 第 6 步（建 `~/.workbuddy/plugins/marketplaces/hzh-local/`）；
3. **平台注册** —— 用**应用内 CLI** 执行 `plugin marketplace add` + `plugin install`（**本节 §2 通道 A**），
   再由**新会话**加载。

> ⚠️ **2026-09-12 重要更正（实测推翻旧结论）**：
> 旧版本指引称「写好 `settings.json` 的 `enabledPlugins` 一行 + 重启即可」——**不成立**。
> 实测（探针法）证明：**仅手写 `enabledPlugins` 时，平台只把该条目「计数」
> （`enabledPluginCount` +1），但因市场未注册而静默丢弃（`marketplaceCount` 恒为 0），
> Stop hook 从不执行**——即所谓「**假闸门**」。
>
> 真实机制：**必须经官方 CLI 把市场注册进 `plugins/known_marketplaces.json`，
> 并把插件安装进 `plugins/cache/<市场>/<插件>/<版本>/`**，平台加载的正是那份 cache 副本。
> 详见 `~/.workbuddy/troubleshooting/plugin-enable.md`。

> **注**：早期（2026-09-06）指引称「必须经插件管理页 GUI 导入，不可脚本化」——亦已推翻：
> 桌面版**并不稳定暴露**「导入本地插件 / 从文件夹安装」入口（实测未找到该按钮）。
> 现主推**可脚本化的 CLI 路径**。

## 1. 前置确认（先自检分发是否完整，再启用）

desen-stop 插件包必须包含以下文件，缺一即加载失败：

```bash
ls -la ~/.workbuddy/hooks/desen-stop/
# 期望看到：
#   .codebuddy-plugin/plugin.json      ← 插件契约入口（平台识别插件靠它）
#   hooks/hooks.json                   ← 声明 Stop 事件命令
#   scripts/desen_stop_hook.py         ← 实际执行脚本
#   README.md                          ← 说明（可选）
```

若缺文件，先重跑 `./bootstrap.sh`（幂等覆盖会补齐仓库最新版），或手动：

```bash
rm -rf ~/.workbuddy/hooks/desen-stop
cp -R <office-kit仓库>/hooks/desen-stop ~/.workbuddy/hooks/
```

自检脚本能否运行（可选，非必需）：

```bash
export PYTHONDONTWRITEBYTECODE=1
python3 ~/.workbuddy/hooks/desen-stop/scripts/desen_stop_hook.py < /dev/null
# 期望：能读到空输入、退出码 0（无内容即无外发判定，静默放行）
```

## 2. 平台启用（通道 A 为主，通道 B 备用）

### 通道 A（推荐 · 可脚本化 · 2026-09-12 实测并已在本机执行）

**第 1 步：确认「本地市场」目录已就位（`bootstrap.sh` 第 6 步产物）**

```
~/.workbuddy/plugins/marketplaces/hzh-local/
├── .codebuddy-plugin/
│   └── marketplace.json          ← 市场清单
└── plugins/
    └── desen-stop/               ← 插件本体（= hooks/desen-stop/ 的全部内容）
        ├── .codebuddy-plugin/plugin.json
        ├── hooks/hooks.json
        ├── scripts/desen_stop_hook.py
        └── README.md
```

`.codebuddy-plugin/marketplace.json`：

```json
{
  "name": "hzh-local",
  "description": "本机自建插件市场（本地目录源）",
  "owner": { "name": "hzh" },
  "plugins": [
    {
      "name": "desen-stop",
      "description": "Stop Hook 插件：会话结束前检测「上云/外发已做却无 desen 脱敏留痕」",
      "source": "./plugins/desen-stop",
      "category": "security",
      "version": "1.0.0"
    }
  ]
}
```

若该目录不存在，本机重跑 `./bootstrap.sh`；或手动按上表建目录后 `cp -R hooks/desen-stop/. <市场>/plugins/desen-stop/`。

**第 2 步：用应用内 CLI 注册市场 + 安装插件** ⭐ 关键步骤

```bash
CLI=/Applications/WorkBuddy.app/Contents/Resources/app.asar.unpacked/cli/bin/codebuddy
MKT="$HOME/.workbuddy/plugins/marketplaces/hzh-local"

"$CLI" plugin validate "$MKT"                        # 先验清单
"$CLI" plugin marketplace add "$MKT"                 # 注册本地目录市场
"$CLI" plugin install desen-stop@hzh-local           # 安装 → 落地 plugins/cache/
"$CLI" plugin marketplace list                       # 核对市场（应含 hzh-local）
"$CLI" plugin list                                   # 核对插件（应显示 Status: enabled）
```

> ⚠️ **若从 WorkBuddy 的（沙箱）终端调用，必须改用「干净环境」，否则所有实命令会静默挂起**
> （`--version`/`--help` 却正常，极易误判为 CLI 坏了）：
> ```bash
> NODE_DIR="$HOME/.workbuddy/binaries/node/versions/22.22.2-3/bin"
> env -i HOME="$HOME" PATH="$NODE_DIR:/usr/bin:/bin:/usr/sbin:/sbin" \
>        CODEBUDDY_CONFIG_DIR="$HOME/.workbuddy" LANG=zh_CN.UTF-8 TERM=dumb \
>   "$CLI" plugin marketplace add "$MKT"
> # …其余命令同理
> ```
> 原因：继承的 `CODEBUDDY_SANDBOX_BROKER_*` / `CODEBUDDY_BROKERED_*` 会让 CLI 误判自己
> 运行在沙箱代理内，转而连接 broker 等待响应。详见 `troubleshooting/plugin-enable.md` §2.5。
> 从**普通终端**（非 WorkBuddy 内）运行时无此问题，直接跑即可。

**第 3 步：重启 WorkBuddy（或新开会话）**

插件在**会话启动时**加载；已开着的会话不会热生效。`plugin install` 自身会提示
`Run /reload-plugins to apply now, or start a new session.`

> **产物**（第 2 步完成后应出现）：
> - `plugins/known_marketplaces.json` → 新增 `hzh-local`（`type: directory`）
> - `plugins/installed_plugins.json` → 新增 `desen-stop@hzh-local`（含 `installPath`）
> - `plugins/cache/hzh-local/desen-stop/1.0.0/` → **平台实际执行的副本**
>
> ⚠️ **维护要点**：平台执行的是 **cache 副本**，不是 `~/.workbuddy/hooks/desen-stop/`
> 分发副本，也不是市场源目录。**改了插件源码后需 `plugin update desen-stop@hzh-local`
> 或重新 `install` 才会生效。**

### 通道 B（GUI / 斜杠命令，备用）

- **斜杠命令**（需在会话内输入）：
  ```
  /plugin marketplace add ~/.workbuddy/plugins/marketplaces/hzh-local
  /plugin install desen-stop@hzh-local
  ```
- **插件页**：`Add Marketplace` 填上面那个本地路径。
  ⚠️ 桌面版是否接受**本地路径**未实测（其占位符提示为 `owner/repo or https://...`）。
- **`/hooks` 面板**：Hooks 仍处 **Beta**，官方称面板是权威入口，外部文件改动需在面板确认。

## 3. 启用后的验证（四级，**务必做到第 3 级**）

**前置：先重启 WorkBuddy / 新开会话。**

**验 1：登记状态（最弱，勿单独采信）**

```bash
python3 -c "import json,os;d=json.load(open(os.path.expanduser('~/.workbuddy/settings.json')));print('enabledPlugins:',[k for k in d.get('enabledPlugins',{}) if 'desen' in k])"
# 期望： ['desen-stop@hzh-local']    ← 空列表 = 未启用
# ⚠️ 这一级「通过」并不代表生效（旧版指引的教训）
```

**验 2：解析链路**（确认市场已注册、插件已安装、cache 副本存在）

```bash
"$CLI" plugin marketplace list      # 应含 hzh-local
"$CLI" plugin list                  # 应含 desen-stop@hzh-local  Status: enabled
ls ~/.workbuddy/plugins/cache/hzh-local/desen-stop/1.0.0/    # 平台实际执行的副本
```
更细的分发完整性校验见 §6。

**验 3：执行级（决定性）—— 探针法**

在 **cache 副本**的 `scripts/desen_stop_hook.py` 的 `main()` 首行临时注入探针
（写 `/tmp/desen-stop-probe.log`），清空建立基线，然后**主动触发一次 Stop 事件**：

```bash
# 无需用户交互即可触发（干净环境；本机实测 8.2s 返回 rc=0）
env -i HOME="$HOME" PATH="$NODE_DIR:/usr/bin:/bin:/usr/sbin:/sbin" \
       CODEBUDDY_CONFIG_DIR="$HOME/.workbuddy" LANG=zh_CN.UTF-8 TERM=dumb \
  "$CLI" -p "只回复两个字：收到"
cat /tmp/desen-stop-probe.log      # 有留痕 = 平台确实调用了该 hook
```

**验证后必须移除探针并还原脚本**（脚本改动会污染 md5 一致性；还原后核对
cache 副本 / 市场源 / `hooks/` 分发副本三处 md5 全等）。

**验 4：行为验证（最强）**

在会话末尾故意做「已外发但无 desen 留痕」的动作，若加载成功，会话结束时会输出
一条 **`⚠ desen-stop` 警示**。

## 4. 生效模式说明

| 环境变量 | 取值 | 效果 |
|---|---|---|
| `DESEN_STOP_HOOK_MODE` | `warn`（默认） | 命中「有外发无留痕」仅输出警示、允许结束 |
| `DESEN_STOP_HOOK_MODE` | `block` | 命中即阻止结束（exit 2），强制回补 desen 审计 |
| `DESEN_STOP_HOOK_OFF` | `1` | 完全跳过本 hook |

> 环境变量需在**启动 WorkBuddy 的进程环境**里可被 hook 读到（hook 是独立子进程，
> 读的是它自己的环境）。若走 GUI 启动，建议在系统级设置里设，而非仅 shell 里 export。

## 5. 常见问题排查

| 现象 | 原因 | 处理 |
|---|---|---|
| 验 1 空列表 | 未登记启用 | 跑 §2 第 2 步 `plugin install` |
| **已登记但 hook 不触发（假闸门）** | **市场未注册 → 插件 id 解析不到** | 查 `plugins/known_marketplaces.json` 是否含该市场、`plugins/cache/` 是否有副本；没有就跑 §2 第 2 步 |
| `plugin list` 里没有该插件 | 只做了文件分发与手写 settings | 必须补 `plugin marketplace add` + `plugin install` |
| **所有 `codebuddy` 实命令静默挂起** | 继承了 `CODEBUDDY_SANDBOX_BROKER_*` / `CODEBUDDY_BROKERED_*` | 用 `env -i` 干净环境重跑（§2 第 2 步注） |
| CLI 报 `env: node: No such file or directory` | `bin/codebuddy` 是 node 脚本，PATH 无 node | PATH 前置 node 目录 |
| 改了插件源码但行为没变 | 平台执行 cache 副本，非源目录 | `plugin update desen-stop@hzh-local` 或重装 |
| 已安装但仍不触发 | 未重启会话；或 hook 未在 `/hooks` 面板确认 | 新开会话；去面板确认 |
| 缺 `.codebuddy-plugin/plugin.json` | 分发不完整 | 回 §1 重跑 bootstrap |
| 误报太多 | 关键词近似检测（`read_table` 等） | 按 README 收紧脚本内 `_EXTERNAL_HINTS`；或设 `=block` 前先用 `warn` 观察 |

## 6. 一键校验脚本 + 机制依据

### 6.1 校验脚本（分发完整性 + 注册状态 + 解析链路 + cache 副本）

```bash
python3 - <<'PY'
import json, os, shlex, subprocess
from pathlib import Path
B = Path(os.path.expanduser("~/.workbuddy")); MK, PL = "hzh-local", "desen-stop"
d = json.load(open(B/"settings.json", encoding="utf-8"))
print("── ① 登记状态 ──")
print("  enabledPlugins:", [k for k in d.get("enabledPlugins", {}) if PL in k] or "（空 = 未启用）")
print("── ② 市场注册 ──")
km = json.load(open(B/"plugins/known_marketplaces.json", encoding="utf-8"))
m = km.get(MK)
print("  known_marketplaces:", "已注册" if m else "❌ 未注册（→ 跑 §2 第 2 步）")
if m: print("    type=%s installLocation=%s" % (m.get("type"), m.get("installLocation")))
print("── ③ 插件安装（平台实际执行的 cache 副本）──")
hits = list((B/"plugins"/"cache"/MK).glob(f"{PL}/*")) if (B/"plugins"/"cache"/MK).is_dir() else []
print("  cache 副本:", [str(x) for x in hits] or "❌ 无（→ 跑 §2 第 2 步）")
ip = json.load(open(B/"plugins/installed_plugins.json", encoding="utf-8"))
print("  installed_plugins:", "已登记" if any(PL in k for k in ip.get("plugins", {})) else "❌ 未登记")
print("── ④ 市场目录解析（分发侧）──")
root = (m or {}).get("installLocation")
mDir = Path(root) if root else B/"plugins"/"marketplaces"/MK
print(f"  marketplaceDir={mDir} 存在={mDir.is_dir()}")
man = mDir/".codebuddy-plugin"/"marketplace.json"; pDir = None
if man.exists():
    e = next((p for p in json.load(open(man, encoding="utf-8")).get("plugins", []) if p.get("name") == PL), None)
    if e and e.get("source") and (mDir/e["source"]).exists(): pDir = mDir/e["source"]
pDir = pDir or (mDir/"plugins"/PL)
print(f"  pluginDir={pDir} 存在={pDir.is_dir()}")
print("── ⑤ hooks 指向 ──")
if pDir.is_dir():
    pj = json.load(open(pDir/".codebuddy-plugin"/"plugin.json", encoding="utf-8"))
    hf = pDir/str(pj.get("hooks", "")).lstrip("./")
    print(f"  plugin.json.hooks={pj.get('hooks')!r} → 存在={hf.is_file()}")
    if hf.is_file():
        for ev, gs in json.load(open(hf, encoding="utf-8")).get("hooks", {}).items():
            for g in gs:
                for h in g.get("hooks", []):
                    s = shlex.split(h["command"].replace("${CODEBUDDY_PLUGIN_ROOT}", str(pDir)))[-1]
                    print(f"  事件 {ev} → {s} 存在={Path(s).is_file()}")
print("── ⑥ 脚本可执行（空输入应 exit 0）──")
s = pDir/"scripts"/"desen_stop_hook.py"
if s.is_file():
    r = subprocess.run(["python3", str(s)], input=b"", capture_output=True,
                       env=dict(os.environ, PYTHONDONTWRITEBYTECODE="1"))
    print(f"  exit={r.returncode}")
print("\n判定：②③ 任一为 ❌ ⇒ 未真正启用（hook 不会执行）")
PY
```

### 6.2 机制依据（2026-09-11 / 09-12 实测）

1. **平台加载插件 hook 的真实条件**：插件所属**市场已注册**（`plugins/known_marketplaces.json`）
   → 插件已**安装**（`plugins/installed_plugins.json` + `plugins/cache/<市场>/<插件>/<版本>/`）
   → `enabledPlugins` 为 true → **会话启动时**加载并合并其 `hooks/hooks.json`。
2. **`settings.json` 的 `extraKnownMarketplaces` 字段不是启用路径**：应用内
   `normalizeMarketplaceConfig()` 只接受 `github` / `git` / `url` / `zip` 四种源，
   **`directory` 被静默丢弃**（该限制**仅作用于这个 settings 字段**，不影响 CLI 路径）。
   实测该键在 2026-09-11 的改动中**从未成功写入**，也因此从未注册成功。
3. **官方文档**：`/Applications/WorkBuddy.app/Contents/Resources/app.asar.unpacked/cli/dist/web-ui/docs/cn/cli/`
   下的 `plugin-marketplaces.md`（§本地路径：`/plugin marketplace add <本地目录>`）、
   `plugins-reference.md`（插件缓存、`${CODEBUDDY_PLUGIN_ROOT}`）、`hooks.md`（`Stop` 事件、
   插件 hooks 合并机制）、`env-vars.md`、`settings.md`。
4. **实测记录**：2026-09-12 在本机对真实配置执行 `marketplace add` + `install`（rc=0），
   并以 `-p` 非交互会话 + 探针取得**执行级**成功证据。详见
   `~/.workbuddy/troubleshooting/plugin-enable.md` 与
   `WorkBuddyConfig/_archive/2026-09-11/desen-stop-运行状态核查-2026-09-11.md` §8。
